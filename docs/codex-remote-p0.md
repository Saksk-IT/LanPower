# Codex Remote P0 实现与验收

日期：2026-10-04。Windows / Cloud / Web `1.16.0`，小程序 `2.1.6`。对应 [改进清单](codex-remote-improvement-plan.md) P0 五项；小程序 P1、资源上传、Git 写操作和 P2 不在本轮范围。

## 五项改动

| 项目 | 完成内容 | 验收证据 |
| --- | --- | --- |
| P0-1 状态一致 | 连接、当前任务、最近同步分开显示；断线显示历史缓存。Host 通知/快照带版本，前端按电脑、会话、任务及读取时序拒绝迟到状态。重连重新读取真实任务、审批、队列与回执 | 旧任务完成不会清除新任务；读取途中新事件优先；受控断线恢复不重发；隔离真实原窗口恢复当前任务 |
| P0-2 参数选择 | 原生参数与下一新任务的选择分开保存。刷新更新原生参数而保留选择；会话间隔离。读取全部原生模型分页及支持的思考强度，显式继承原窗口设置 | 刷新/切换后模型选择保留；能力选项与发送参数一致。排队和引导沿用原任务参数，页面说明这一行为 |
| P0-3 草稿与回执 | 按电脑/会话保存页面内存草稿、图片、技能、文件引用和队列编辑状态。每次提交先生成稳定编号；目标电脑先持久记录回执再派发。已接受、失败、结果待确认分开显示 | 多会话草稿/图片不串；接受后丢失响应，重连查询回执，仅执行一次；明确未发送则恢复草稿；不确定先查证，人工确认未执行后可恢复输入 |
| P0-4 大历史 | 超限页从 8 轮依次降至 4/2/1 轮。大项或大轮次替换为可完整取回的引用，按字符块下载。进度、取消、继续和游标检查；跳至开头只保留游标和当前页，导出逐轮组装 Blob | 180 轮及 17 MiB 单项完整读取；UTF-16 代理对边界无乱码；取消后继续不重复、不缺项；导出不会把历史反复转换为全量 JSON 字符串 |
| P0-5 原生控制恢复 | 操作前复核当前授权、任务和原生审批。原生审批编号去重；桌面已处理请求及时移除。审批等真实处理回执；队列操作和停止捕获原会话/任务标识；不支持接口明确反馈 | 隔离原窗口任务：原生用户回复请求、队列增改删、断开后恢复、桌面先回复、重复审批拒绝、任务完成、停止正确任务、原回执查询均通过 |

读取旧消息时保留已有历史和阅读位置；“跳至开头”按窗口前后翻页，“返回最新”恢复实时阅读。重新连接只重新读取状态，不重放任务、队列提交或审批决定。

## 存储和大小边界

- Cloud 帧仍为 1 MiB，单个 RPC 结果仍为 16 MiB；有界内存中继，不建立正文数据库、副本或日志。新 RPC 同时经过 Cloud、Service、Host 白名单和参数校验。
- 原窗口 Renderer 与 Host 的历史临时缓存分别最多 64 MiB，按字符串的 UTF-16 占用计算；空闲引用 10 分钟过期，读取延长有效时间，清理/退出释放。单份内容超过缓存上限会明确提示在原窗口取回，不宣称无限大小支持。
- 历史块最多 64 Ki 个 UTF-16 字符，分块避免切断代理对；引用绑定会话。过期或被淘汰后刷新对应轮次重新下载。浏览器分页/分块读取进行节流以符合既有 Cloud 请求频率限制。
- 大项下载为完整可见 JSON；完整导出还原原项/轮次，而非导出占位符。隐藏与加密推理在缓存前剔除。
- 草稿、附件和下一发送选择仅保存在当前页面内存，刷新或退出页面清除；不写浏览器本地存储。刷新后恢复草稿的隐私与清理设计仍保留给后续工作。
- 目标电脑 `%LOCALAPPDATA%/LanPower/codex-submissions.json` 仅保存提交/会话编号、方法、参数摘要哈希、回执状态、任务/队列编号及时间，不保存提示词或附件。最多 512 条，未确认回执不淘汰；满容量时拒绝新派发。Host 重启后的发送中记录转为结果待确认。同编号但不同参数或会话会被拒绝。
- 本机回执文件被 Git 忽略，发布检查也拒绝它。传输中断、请求超时或 Host 重启不能证明“未执行”；查询未知结果不会开放直接重试。

真实验收仅断开 LanPower 自己的连接，不关闭官方 Codex、不结束其他聊天。临时项目没有执行命令、访问其他项目、联网取资料或修改项目文件；模型调用使用原窗口已有登录。报告只记录布尔验收结果与网络类型，保存于忽略目录 `private/codex-remote-p0`。

## 可重复验证入口

自动化入口为 `remote_ui/tests/reliability.test.ts`、`windows/LanPower.UnitTests/CodexReliabilityTests.cs`、`cloud_app/tests/test_codex_reliability.py` 与 `tests/test_codex_p0_browser.cjs`；浏览器专项使用受控接口，不触发真实模型任务。

`tests/native_codex_recovery/NativeRecovery.csproj` 是手动真实验收程序，不属于常规自动测试。准备好原窗口、模型可用额度和本机调试连接后，从仓库根目录运行：

```powershell
dotnet run --project tests/native_codex_recovery/NativeRecovery.csproj -c Release
```

它创建并仅授权临时项目，提交两次真实计划模式任务以产生用户回复请求，操作仅该聊天，结束时停止剩余任务并归档。布尔检查失败或超时返回失败状态；报告不包含会话正文和凭据。使用自己的可用 .NET 10 SDK 路径替代 `dotnet` 即可。

## 人工验收仍开放

本轮受控断线、取消、后台恢复逻辑和本机原窗口验收，不等于真实弱网、手机操作系统后台、电脑物理休眠、微信真机或 5G 验收。这些仍需在用户设备上逐项检查：断网恢复后的审批/队列、休眠前后原任务、授权变化和控制页占用、微信后台/键盘、5G 长会话下载。未经实测的条件不关闭验收项。

本机 Docker 与 Windows 升级记录见 [本机开发指南](local-development.md)。本轮不推送远程仓库、不部署正式 Cloud、不发布公开 Release。

新网页的历史范围和提交回执字段要求 Windows 组件一起更新至 `1.16.0`。升级中曾出现 Cloud 已更新、Windows 仍为 `1.15.2`，点击会话触发旧白名单拒绝而导致 Codex 通道断开；本轮已先更新 Windows 并核对实际通道恢复，保留用户手工页面验收。
