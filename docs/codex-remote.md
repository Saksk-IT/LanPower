# Codex Remote 使用与验收

LanPower 1.14.0 的远程开发入口包括微信小程序 `2.1.2` 的 **Codex** 页面，以及 Cloud 的 `/remote` 网页/PWA。网页复用成熟 Vue 会话、输入、审批和队列组件，直接接入已打开的原 Codex 窗口；小程序保留原生页面。选择电脑后自动识别项目与最近会话。开发任务在自己的 Windows 电脑执行，Codex 登录、项目代码和会话历史留在电脑。实现及本机真实验证见 [原窗口整合说明](codex-original-window.md)。

## 微信小程序入口

完整导入新版 `mini_program` 并重新编译。在自己的 Cloud「手机授权 → 修改手机权限」中为这部手机开启 **Codex Remote 远程开发**，已有手机无需重新扫码；Windows 端仍需开启远程开发及项目授权。进入底部 **Codex** 后选择电脑，可查看会话、新建任务、实时跟进输出、补充要求、暂停并处理单次审批。主题选项可跟随系统或选择浅色/深色。

小程序入口至少需要 Cloud `1.12.0`；原窗口和新版网页需要 Windows、Cloud 同步至 `1.14.0`。微信公众平台同时配置 HTTPS request 与 WSS socket 合法域名。网页和小程序共享每台电脑一个控制连接，另一页面占用时不会抢占。桌面控制优先使用下文的原窗口入口。界面截图、导入步骤和第一版验证记录见 [Codex Remote 小程序](codex-remote-mini-program.md)。

## 准备与首次连接

1. 构建并安装 Windows 1.14.0，同时将自己的 Cloud 更新到 1.14.0。公开 v1.6.1 安装器和正式 Cloud 1.7.2 暂不提供新版 Codex Remote。更新前备份原配置和数据库，保留配对身份。
2. 在准备远程使用的 Windows 用户下登录 Codex。已安装 Codex 桌面程序时，LanPower 能检测其内置 Runtime；官方 CLI 同样兼容，不需要重复配置登录。本轮验证使用 Runtime `0.159.0`；安装器不包含 Codex 或登录凭据。
3. 在 LanPower「远程连接」连接自己的 Cloud，启用「允许 Codex Remote 连接这台电脑」，保留勾选「自动识别本机 Codex 项目与最近会话」并保存。不再要求逐个添加项目。可关闭自动识别，只授权手动目录；只接受普通本机目录，不接受网络路径、符号链接或目录联接。
4. 登录 Cloud 的「Codex Remote」，选择电脑即自动连接；仅一台电脑或从 Windows 打开指定电脑链接时会自动选择。首页展示跨项目最近会话及项目分组，点击即可读取已有消息，查看操作不会立即接管或恢复桌面会话。在任意项目中可开始新会话。
5. 输入消息并发送；任务运行时可选择引导当前任务或加入原生队列。暂停收到本机确认后才显示已暂停，已有修改保留，再发消息即可继续。执行过程、工具和 Diff 可展开，输入栏可选择模型；会话菜单提供刷新、重命名、分支、回退与归档。命令或文件审批仍只允许单次批准，文件浏览与语音等操作留在原窗口。
6. 手机可在支持的浏览器中添加页面到主屏幕。电脑离线时，先使用页面的「唤醒电脑」或既有小程序唤醒；此操作仍需要已配置且可用的 Wake Gateway。上线后连接程序自动恢复。

Cloud 必须是 Windows 和浏览器都可访问、证书可信的 HTTPS 地址，反向代理需支持 WebSocket Upgrade。电脑只发起 HTTPS/WSS 出站连接，不需要端口映射。现有本机开发地址 `https://localhost:8443` 只供当前电脑使用，手机自己的 localhost 不能连接它；正式公网验收需用户另行部署 Cloud 1.14.0。

## 官方桌面与网页双端控制

在 Windows「远程连接」保存项目授权后，点击 **连接原 Codex 窗口**。该入口连接当前用户已经打开的官方窗口及其原服务，无需迁移活动任务或另开工作窗口。再从网页选择同一电脑和会话即可共同控制。如果本机调试接口未开启，按钮会提示启动参数；先完成原任务，再手动按提示启动，LanPower 不自动关闭原窗口。备用入口 **打开备用共享窗口** 保留原共享服务方案。

- 运行中输入文字并发送，会引导同一轮任务；空输入栏的蓝色方块用于暂停，等待实际中断确认后才显示已暂停。
- 选择排队加入 Codex 原生会话队列。桌面显示相同消息；网页可修改、移除、排序和立即执行。下一轮的模型与权限沿用原生会话设置。
- 两端可以继续同一会话，无需「交还桌面」。每条会话独立维护当前任务编号，上一轮的暂停不能覆盖新轮运行状态。
- 退出或刷新网页只断开连接，共享服务继续运行。撤销远程授权不终止共享桌面任务，重新授权后重新读取状态，不自动重发任务。

原窗口入口使用本机官方桌面的内部接口，当前验证为桌面 `26.928.1915.0`、CLI `0.159.0`；升级官方应用后需复核兼容性。若选择备用共享入口，另一个独立窗口的活动任务仍不能迁移到备用服务，应等原任务完成后再切换。此接入不等同于 ChatGPT 官方托管 Remote 的配对。

未启用原窗口或共享接入时保留只读观察：独立窗口的消息与生命周期约每 2 秒读取，系统写锁用于判断占用，旧轮暂停不会被当成当前状态。页面禁用该路径的发送和暂停。新版网页从原服务按每页 8 轮读取历史，最多保留 128 轮及有界文本，完整记录仍保存在电脑。备用入口的历史证据见 [共享控制验证](codex-remote-takeover.md)。

## 状态与操作

| 页面状态 | 含义与下一步 |
|---|---|
| 电脑未连接 Relay | 电脑离线、Cloud 旧版或网络不可达；先查看电源状态与 Cloud 连接 |
| 用户 Host 未运行 | Windows 尚未登录用户，或 Host 未启动；在电脑打开 LanPower |
| 本机尚未授权 | 在电脑启用远程开发，勾选自动识别或添加手动项目后保存 |
| Runtime 启动中 | 用户 Host 正在启动本机 Codex |
| Runtime 未就绪 | 在电脑检查 CLI、登录和运行环境，再断开并连接 |
| Codex 已连接 | 自动读取项目与会话；尚未登录时仍会提示在本机完成登录 |
| 桌面正在运行 · 同步查看 | 根据本机生命周期确认仍在运行，每 2 秒读取已保存的进度；当前不可网页引导或暂停 |
| 桌面已连接 · 本轮已结束 | 当前轮次已结束，桌面仍持有会话；等待释放后可继续 |
| 桌面已连接 · 状态待确认 | 缺少可确认的当前生命周期；不会把旧暂停或写锁当成当前运行状态 |
| 另一页面正在控制 | 每台电脑只允许一个控制页面；关闭另一个页面再连接 |

Windows 已登录是必要条件。锁屏通常保留用户会话；注销会结束用户 Host。唤醒电脑不等于完成 Windows 登录，电脑从关机启动但没有登录用户时，远程开发仍不可用。MVP 不设置自动登录，也不会用 SYSTEM 代替用户运行 Codex。

## 断线、恢复与审批

- 关闭或刷新浏览器只断开控制连接，已发任务继续在电脑运行。重连读取活动任务、最近 Diff、未完成审批和本机会话；新版网页仅持久保存主题偏好，不保存正文，也不会自动重发任务。发送结果未知时先查看会话确认。
- 独立模式的空会话在首次任务前由 Host 内存保留，最多 32 个，Host 重启后可能消失。共享模式会补读原生服务已加载的新会话，首次消息尚未保存时仍可读取和继续；Host 重启后可从仍在运行的共享服务恢复，首次任务后的历史由本机 Codex 管理。
- 每条会话各自维护活动编号，可同时跟进不同会话。共享模式中同一轮接受引导和暂停，队列由原生服务管理；独立模式最多保留 8 个自有执行会话。
- 命令和文件只可单次审批。带额外文件目录的请求必须精确匹配本机授权项目根目录；额外文件系统权限和永久策略变更不可在网页批准。网络权限最多当前任务 turn；MCP 交互登录/授权需在电脑处理。
- 独立模式的未处理审批 5 分钟后拒绝；共享模式由原生服务管理审批生命周期，Host 不自行拒绝桌面待审批。浏览器断线后审批保留在本机，重新连接后可继续处理；到期或 Runtime 已解决的审批不能再次批准。
- 关闭本地授权或修改范围会断开远程连接。共享服务独立于 Host，桌面任务继续；独立模式会结束 Host 自有进程。切换为共享模式时，运行中的旧远程任务先完成，不因单纯切换模式被终止。
- 服务/Cloud 重启或网络断开不重发任务。共享模式的 Host 退出只断开自己的连接；Windows 注销或共享服务退出后，恢复依赖本机会话历史。

## 保存与安全边界

用户授权配置位于 `%LOCALAPPDATA%\LanPower\codex-remote.json`，不保存 OpenAI 密钥。Host 使用当前用户已有的 Codex Home，不复制到 ProgramData 或 Cloud。卸载保留 LanPower 原配对与用户配置，并移除用户 Host 启动项。

Relay 使用有界内存队列，不把提示词、输出、完整代码、Diff 或审批正文保存到数据库和日志。审计仅含账户/设备编号、事件类型和时间。PWA 只缓存版本化公开静态文件，HTML、接口、会话、任务和 Diff 不进入 Service Worker 缓存；不支持离线发任务。

TLS 在 Cloud 终止，当前 MVP **不是端到端加密**，自建 Cloud 的运维者属于可信边界。网页新建任务按 `workspace-write` / `on-request` 运行；订阅已有共享会话不覆盖桌面权限，原生队列沿用会话设置；这限制写入和需要批准的工具操作，但不是完整文件保密沙箱，不保证阻止读取 Windows 用户可读文件。请只授权可信项目，仔细审核命令，保护 Cloud 登录及 Windows 用户账户。

Relay 单帧最多 1 MiB，队列最多 32 帧且累计 8 MiB，最多 64 个待回复/审批，10 秒最多 120 个浏览器请求。超限断开而不自动重试任务。页面保留最多约 256 KiB 实时文字和最近 Diff、5,000 行 Diff；较大历史或输出需要回到本机查看。Cloud 当前仅支持单个 worker/副本。

## 历史 1.11.0 会话交还（2026-10-02）

“已在另一个应用中打开”表示另一个 Codex 服务仍持有此会话。以前网页恢复会话后，即使任务已完成或暂停，Host 也一直保留该服务，所以桌面无法恢复。这不是网络断开，也不能通过取消只读检查获得双端控制。

1.11.0 把目录/历史读取连接与会话执行连接分开，每条远程会话使用独立执行进程，最多同时保留 8 个会话。当前会话的活动编号、引导和暂停独立维护；另一会话运行不会覆盖本会话的控件。不同进程内相同的原生审批编号会转换为唯一远程编号，并在本机正确还原。

远程任务完成或确认暂停后，通常约 2–4 秒自动释放执行进程和写锁。顶部菜单“交还桌面”可立即释放闲置会话，随后在桌面点击“重试”恢复。网页再发消息会重新恢复同一条已保存会话。存在未结束任务、子任务、审批或后台命令时不释放；后台检查接口不可用时返回无法确认，而不会强行结束。新建但尚未发送消息的空会话不保证持久化，主动交还后需重新新建。

官方 Runtime 0.159.0 的独立目录验收确认：网页恢复所持写锁能阻止另一连接；交还后系统写锁释放，另一连接可恢复同一会话；另一连接持有时网页继续受只读保护；真实暂停、自动释放与 Remote 再次恢复通过，测试文件未修改。此测试使用两个实际 Runtime 连接，未通过原生桌面 UI 验收共享控制。

Windows 71 项、Cloud 187 项测试通过，新增会话隔离、审批编号冲突、已处理通知、自动释放、再次恢复、后台命令保护和 Cloud 交还 RPC 验证。浏览器在 1440/390/320px 验证交还菜单、多任务控件、桌面只读进度、布局及旧缓存更新；交互采用受控响应。官方 Runtime 的写锁和接续另行真实验证。

本机 Windows 和 Docker 已更新至 1.11.0，安装的三个程序与构建哈希一致。LAN 配置及用户授权逐字节保留，Cloud 地址与设备身份保持，凭据正常续期轮换。Cloud/Caddy 健康，SQLite 一致备份及九张身份/配置表的主键和引用保持。实际登录浏览器确认正常 HTTPS 与安装 Host 的 runtime_ready；另一页面持有控制连接，本轮未抢占它执行真实网页任务，也未通过原生桌面 UI 验收共享控制。

这些改动解决网页与桌面的交接。原生桌面当前的独立 stdio 任务仍不能由网页同时引导或暂停；真正双端操作需要桌面与 Host 连接同一个服务，不能将当前交接能力称为完整原生接管。
