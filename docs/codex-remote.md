# Codex Remote 使用与验收

LanPower 1.9.0 的远程开发入口是 Cloud 的 `/remote` 网页，也可添加为 PWA。选择电脑后自动识别项目与最近会话，手机先显示会话列表，再进入消息详情。开发任务在自己的 Windows 电脑执行，Codex 登录、项目代码和会话历史留在电脑。

## 准备与首次连接

1. 构建并安装 Windows 1.9.0，同时将自己的 Cloud 更新到 1.9.0。公开 v1.6.1 安装器和正式 Cloud 1.7.2 暂不提供新版 Codex Remote。更新前备份原配置和数据库，保留配对身份。
2. 在准备远程使用的 Windows 用户下登录 Codex。已安装 Codex 桌面程序时，LanPower 能检测其内置 Runtime；官方 CLI 同样兼容，不需要重复配置登录。本轮验证使用 Runtime `0.159.0`；安装器不包含 Codex 或登录凭据。
3. 在 LanPower「远程连接」连接自己的 Cloud，启用「允许 Codex Remote 连接这台电脑」，保留勾选「自动识别本机 Codex 项目与最近会话」并保存。不再要求逐个添加项目。可关闭自动识别，只授权手动目录；只接受普通本机目录，不接受网络路径、符号链接或目录联接。
4. 登录 Cloud 的「Codex Remote」，选择电脑即自动连接；仅一台电脑或从 Windows 打开指定电脑链接时会自动选择。首页展示跨项目最近会话及项目分组，点击即可读取已有消息，查看操作不会立即接管或恢复桌面会话。在任意项目中可开始新会话。
5. 输入消息并发送，查看实时回复、工具输出、任务计划、耗时及折叠 Diff。自己的远程任务运行中，发送按钮变为「引导」，在同一轮补充要求；「暂停任务」调用官方中断接口，收到完成通知后显示已暂停，已有修改保留，再发消息即可继续。命令或文件审批仍只允许单次批准。
6. 手机可在支持的浏览器中添加页面到主屏幕。电脑离线时，先使用页面的「唤醒电脑」或既有小程序唤醒；此操作仍需要已配置且可用的 Wake Gateway。上线后连接程序自动恢复。

Cloud 必须是 Windows 和浏览器都可访问、证书可信的 HTTPS 地址，反向代理需支持 WebSocket Upgrade。电脑只发起 HTTPS/WSS 出站连接，不需要端口映射。现有本机开发地址 `https://localhost:8443` 只供当前电脑使用，手机自己的 localhost 不能连接它；正式公网验收需用户另行部署 Cloud 1.9.0。

## 桌面会话与控制边界

本机桌面 Codex 当前使用独立 stdio app-server，未提供可供 LanPower 连接的共享控制端点。另一个 Runtime 能读取持久会话，但不能直接引导或中断桌面 Runtime 中正在执行的任务。1.9.0 会检查 Codex 的实际进程写锁；桌面占用时显示「桌面占用 · 同步查看」，约每 3 秒读取最新已保存消息，并禁用发送和暂停。锁文件在进程结束后可能残留，只有仍被系统持有的锁才判为占用。

桌面释放会话后可以在 Remote 继续；新建或已经恢复到 Remote 的任务可以实时引导和暂停。当前实现没有达到 ChatGPT 原生 Remote 对已运行桌面任务的完全接管能力，不会通过强行结束桌面程序或重复启动同一任务来模拟暂停。完整历史保留在 Codex，页面读取近期最多 8 轮及有界文本；更早或较大内容仍在电脑查看。

## 状态与操作

| 页面状态 | 含义与下一步 |
|---|---|
| 电脑未连接 Relay | 电脑离线、Cloud 旧版或网络不可达；先查看电源状态与 Cloud 连接 |
| 用户 Host 未运行 | Windows 尚未登录用户，或 Host 未启动；在电脑打开 LanPower |
| 本机尚未授权 | 在电脑启用远程开发，勾选自动识别或添加手动项目后保存 |
| Runtime 启动中 | 用户 Host 正在启动本机 Codex |
| Runtime 未就绪 | 在电脑检查 CLI、登录和运行环境，再断开并连接 |
| Codex 已连接 | 自动读取项目与会话；尚未登录时仍会提示在本机完成登录 |
| 桌面占用 · 同步查看 | 可以看最新消息；需桌面释放会话后才能继续或控制 |
| 另一页面正在控制 | 每台电脑只允许一个控制页面；关闭另一个页面再连接 |

Windows 已登录是必要条件。锁屏通常保留用户会话；注销会结束用户 Host。唤醒电脑不等于完成 Windows 登录，电脑从关机启动但没有登录用户时，远程开发仍不可用。MVP 不设置自动登录，也不会用 SYSTEM 代替用户运行 Codex。

## 断线、恢复与审批

- 关闭或刷新浏览器只断开控制连接，已发任务继续在电脑运行。重连读取活动任务、最近 Diff、未完成审批和本机会话；只在页面会话存储中保留选中会话编号，不保存正文，也不会自动重发任务。发送结果未知时先查看会话确认。
- 空的新会话在首次任务前由 Host 内存保留，最多 32 个。官方 app-server 尚未持久保存的空会话，在 Host 重启后消失；首次任务后的历史由本机 Codex 管理。
- 每台电脑一个 Runtime、一个活动远程任务。可浏览其他会话，但要等活动任务完成或中断后再发送新任务。
- 命令和文件只可单次审批。带额外文件目录的请求必须精确匹配本机授权项目根目录；额外文件系统权限和永久策略变更不可在网页批准。网络权限最多当前任务 turn；MCP 交互登录/授权需在电脑处理。
- 未处理审批 5 分钟后拒绝。浏览器断线后审批保留在本机，重新连接后可继续处理；到期或 Runtime 已解决的审批不能再次批准。
- 关闭本地授权或修改项目配置会结束 Runtime 及其工具进程，终止中的任务可能已有部分修改，应在本机检查代码。Host 使用 Windows Job Object，进程崩溃或卸载退出时结束其子进程。
- 服务/Cloud 重启、网络断开不自动重发开发任务。Host 保持用户 Runtime，重连绑定新的控制会话；Windows 注销、Host 退出后的恢复依赖 Codex 的本机会话历史。

## 保存与安全边界

用户授权配置位于 `%LOCALAPPDATA%\LanPower\codex-remote.json`，不保存 OpenAI 密钥。Host 使用当前用户已有的 Codex Home，不复制到 ProgramData 或 Cloud。卸载保留 LanPower 原配对与用户配置，并移除用户 Host 启动项。

Relay 使用有界内存队列，不把提示词、输出、完整代码、Diff 或审批正文保存到数据库和日志。审计仅含账户/设备编号、事件类型和时间。PWA 只缓存版本化公开静态文件，HTML、接口、会话、任务和 Diff 不进入 Service Worker 缓存；不支持离线发任务。

TLS 在 Cloud 终止，当前 MVP **不是端到端加密**，自建 Cloud 的运维者属于可信边界。Runtime 按 `workspace-write` / `on-request` 运行；这限制写入和需要批准的工具操作，但不是完整文件保密沙箱，不保证阻止读取 Windows 用户可读文件。请只授权可信项目，仔细审核命令，保护 Cloud 登录及 Windows 用户账户。

Relay 单帧最多 1 MiB，队列最多 32 帧且累计 8 MiB，最多 64 个待回复/审批，10 秒最多 120 个浏览器请求。超限断开而不自动重试任务。页面保留最多约 256 KiB 实时文字和最近 Diff、5,000 行 Diff；较大历史或输出需要回到本机查看。Cloud 当前仅支持单个 worker/副本。

## 1.9.0 本轮验证（2026-10-02）

- Windows 63 项单元测试和 42 项桌面检查通过，覆盖自动项目发现、不选目录读取最近会话、引导任务编号校验、真实写锁及残留锁识别，原 LAN / 小程序回归通过。
- 用户 Host 拒绝越权目录或过期操作时返回固定错误类别并继续运行；隔离服务管道验证拒绝后仍可正常读取模型，避免错误操作导致 Host 退出。
- 真实 HTTPS Chromium 在 1440/390/320px 验证自动连接、项目分组、列表/详情切换、消息/Diff、同轮引导、暂停确认、桌面只读、HTML 文本展示和旧 PWA 缓存清除。交互 Runtime 采用受控响应；正常浏览器默认编号与计时函数参与验证。
- 已安装 Service WSS Agent、当前用户 Host 与真实浏览器自动读取本机 9 个项目/工作目录、最近会话和当前桌面占用会话；页面无脚本错误，查看不会接管桌面任务。
- 使用当前用户已登录的官方 Runtime，在独立临时目录完成创建、发送任务、实际接收引导并回复、实际中断确认；测试文件内容保持不变，测试会话随后归档。
- 本机 Docker / Windows 更新至 1.9.0，数据库先做 SQLite 一致备份，保留原数据卷和证书。Windows 三个程序的哈希与构建产物一致，LAN 配置及用户授权逐字节保留，Cloud 地址和设备身份保持；加密凭据因正常续期轮换而变化。
- 原图中的 `Illegal invocation` 在干净浏览器未复现；新版本保留浏览器原生方法接收对象，并递增静态资源/PWA 版本。当前实际链路读取正常，不能将其归因为已确认的 Windows 网络故障。
