# 故障排查

| 现象 | 检查和处理 |
|---|---|
| Windows 桌面显示服务未连接 | 检查 LanPowerService 是否运行；桌面端通过命名管道连接。不要以开放公网端口解决。 |
| 局域网地址已变化 | 在桌面“设置与更新”启用所选网卡的自动更新，或重新检测并保存固定模式；让手机重新扫码确认地址。 |
| 网络设置未完成 | 确认所选物理网卡已连接且有私有 IPv4 地址，检查服务日志与防火墙权限。远端 LAN 请求暂停时，Cloud 和本机配对页仍可使用。 |
| 桌面无法检查更新 | 检查网络；系统代理路径失败时，关闭“更新检查使用系统代理”重试。下载页只提供本项目正式发布信息，不会自动执行安装。 |
| Cloud 不可用，但在家中 | 使用已配对的局域网入口；小程序缓存的 LAN 连接可独立尝试。 |
| 网页能访问 Cloud，Windows 服务配对失败 | 服务以 LocalSystem 运行并使用直连 HTTPS；核对系统实际解析和出口。TUN 透明代理仍可能接管流量，先检查自己的 Cloud 域名命中的路由；虚拟 DNS 地址本身不表示故障。必要时在当前订阅的规则编辑器保存仅该域名的 `DOMAIN,自己的Cloud域名,DIRECT` 规则，并确认运行配置生效。保留 HTTPS 证书验证，不通过固定 Cloudflare 节点地址解决。 |
| 在线电脑无法远程开机 | 在线控制与唤醒是不同能力；检查 Wake Gateway 关联、本地电脑配置和网关在线状态。 |
| 网关在线但开机不可用 | 两边的 Windows 编号必须一致，网关本地需配置 MAC 和广播地址。已移除电脑的旧编号不能继续使用。 |
| 开机显示已送达但电脑没启动 | 检查固件 WOL、网卡唤醒设置、电源状态、MAC 和广播网段；WOL 无法确认物理启动成功。 |
| 备用控制不可用 | Windows Cloud Agent 需离线，网关及 LAN 电脑需在线；网页“允许备用控制”和本地 `backup_relay` 都要开启。 |
| 命令显示未在时限内确认 | 查看 Cloud、设备和网关日志。已发出动作可能已执行，先核对真实状态，再决定是否重新操作。 |
| Windows 或网关需要重新连接 | 检查是否被移除、刷新凭据是否过期或刷新响应丢失；在网页移除旧记录后重新注册并重建网关关联。 |
| 小程序要求重新扫码 | 独立客户端授权已失效或刷新中断；在 Cloud 生成新的客户端二维码。原 LAN 关联可继续保留。 |
| Passkey 登录失败 | 使用配置中的实际 HTTPS 域名，检查系统时间；备用 Passkey 或未使用恢复码可恢复登录。 |
| 初始化码不存在 | 已完成初始化时文件会删除；使用登录页，不要删除数据库来重新初始化。 |
| Docker 更新后像全新安装 | 检查数据挂载是否从原 `./data` 误改为新数据卷。停止服务并恢复原挂载，不要覆盖原数据。 |
| HTTPS 证书未生成 | 核对域名 DNS 和公网 80/443；已有代理占用端口时关闭内置 Caddy profile。 |
| 路由器脚本提示解释器或语法错误 | 检查脚本 LF 换行；按网关 README 从 Git 导出源码，不使用带 CRLF 的部署脚本。 |
| 网关拒绝启动并提示执行记录损坏 | 保留损坏文件并检查存储。不要删除重放记录后立即重试可能已执行的命令。 |

收集版本、发生时间、设备状态、所选路径和经过脱敏的错误即可。不要粘贴配对二维码、LAN Token、Cloud Token、恢复码、Authorization 头或证书私钥。

Windows 连接日志会保留异常类型、HResult、HTTP 状态和系统错误码，帮助区分 DNS、TLS、网络和授权问题；异常消息、响应正文和 URL 不写入日志。Clash Verge Rev 的订阅规则保存位置可参考其[官方扩展说明](https://www.clashverge.dev/guide/extend.html)。

真实电源验收应安排在可恢复设备上，先保存工作并准备本地操作方式。完整开发和验收状态见 [架构说明](architecture-v2.md)。
