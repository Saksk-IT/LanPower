# Windows 与 Cloud 自动恢复连接

Windows / Cloud / Web：**1.22.1**；配套小程序：**3.3.1**。日期：2026-10-05。

## 故障与修复

旧版 Windows 使用一次性刷新凭据获取访问凭据，发送前保存 `RefreshPending` 标记。启动时网络尚未就绪、续期途中休眠、Cloud 返回 502、响应丢失或服务中断，都可能留下未完成标记。为了避免重放已使用的凭据，旧服务停止续期并显示「需要重新连接」。这条路径使相同的开机或恢复操作是否需要重新配对，取决于续期被中断的时机。

另一条路径是访问凭据在休眠期间过期，或旧请求在其他线程续期之后才返回 401。旧服务可能把访问凭据失效直接判为长期授权失效。

新版本优先使用 `POST /api/v2/windows/renew`，保留长期授权凭据与设备身份，只更新短效访问凭据，并延长仍有效的长期授权。续期响应丢失、网络超时、取消、502 或进程重启后，可以使用原凭据安全重试。新接口复用设备授权校验，不需要数据库迁移。

心跳、命令轮询或回执收到 401 后，Windows 丢弃对应的旧访问凭据并自动续期，再重试一次。迟到的 401 不影响较新的凭据或另一台新配对的设备。只有续期接口明确返回 401/403，才记录 `ReconnectRequired` 并要求重新配对；连接故障显示「连接中断」并继续重试。

已有的 `RefreshPending` 标记会先通过新接口恢复。云端仍认可原凭据时，自动清除标记；旧的一次性凭据已经被消耗、授权已撤销或已过期时，新接口不会恢复无效授权，也不会自动创建另一台设备。

## 升级与兼容

Windows 和 Cloud 均需更新至 **1.22.1**，才能完整覆盖续期中断后的恢复。仅更新 Windows、继续使用旧 Cloud 时，只有新接口明确返回 404/405 才允许使用旧的一次性接口；网络错误、401/403、5xx 和无效响应不会触发降级。旧接口发生结果不明的中断时仍可能需要重新配对。

沿用原 ProgramData 配置、DPAPI 加密凭据、LAN 配对、设备编号和手机授权。访问凭据有效期仍为 15 分钟；长期授权每次成功续期延长 30 天，连续离线超过有效期仍需重新授权。主动断开、网页撤销设备或撤销管理员权限保持生效。

## 验证

自动检查覆盖并发续期、响应丢失与进程重启、续期取消、DNS/超时/502、无效响应、休眠 12 小时后的访问凭据过期、迟到的 401、写盘失败、旧接口 404/405 兼容、授权撤销与设备类型隔离。Agent 演练确认原配对恢复心跳与命令处理。

本机安装、Docker 更新与服务重启结果记录在 [本机开发](local-development.md)。自动检查模拟休眠期间的时间流逝，不等于真实关机、睡眠或休眠后的实机验收。完整实机检查：关闭或休眠电脑，恢复后等待网络就绪，确认应用与 Cloud 自动上线且设备编号不变，再发送一次只读状态查询；不要点击「断开 Cloud」或删除配对记录。
