# 网页 Codex 图片发送

修复版本：Windows / Cloud / Web `1.20.2`，小程序随产品版本更新至 `3.1.4`。本次行为调整用于网页输入框；小程序图片输入行为未扩展。

此前网页上传时只检查单张图片，发送时才检查所有图片的编码总量。两张分别能够添加的截图，合计却可能超出中继的单帧预算，因此出现“700000 / 850000 字符”的内部限制提示；从队列或历史恢复的原图也会遇到同类问题。

## 使用行为

- 新添加、粘贴的图片和从草稿、队列、历史恢复的图片，在发送前统一按整组大小处理。一次最多添加 4 张图片。
- 小图片保留原始字节。需要处理时优先尝试 PNG 无损编码，再尝试高质量 WebP，必要时逐步缩小尺寸；保留图片顺序和透明背景。
- GIF 与带动画标记的 WebP 保留原始字节；不为缩小体积而静默变成静态图片。动图自身或其合计过大时提示减少图片、选择较小原图或在原窗口添加。
- 处理时显示“正在处理图片…”，暂时锁定输入和发送，避免重复提交。切换会话、替换草稿或关闭页面后，旧处理结果不会发送到新会话。
- 格式、数量、压缩或发送失败时保留草稿。错误提示说明可采取的操作，不再展示内部编码字符数。

Cloud、Windows Service / Host 继续分别执行原有协议校验；单帧、队列和内存预算保持有界。具体传输约束见 [中继协议](codex-remote-protocol.md)，它们不代表模型的图片大小上限。

## 验证

网页单元测试覆盖合计超限、原图保留、动图预算、逐步缩小、资源释放、格式及数量检查。真实浏览器在隔离 RPC 下用有效 PNG 图像验证新图发送、编辑队列消息、4 图、仅图片输入、发送拒绝恢复和处理期间切换会话。

入口：`tests/test_codex_image_submission_browser.cjs`。两张原图合计 `997224` 字符，发送前处理后为 `661081`；4 图发送为 `639348`，均通过单帧与图片总量检查。1440 / 390 / 320px 无横向溢出，浏览器错误为 0。

浏览器发送响应使用隔离夹具，未向用户原会话发送新的推理任务；实际手机、微信真机和公网链路仍需人工验收。本机更新记录见 [开发环境](local-development.md)。
