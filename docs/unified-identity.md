# 统一身份实现与验证

本阶段补齐 Cloud 管理员的 Passkey、初始化与恢复码，以及 Windows 发起配对、网页批准、独立设备凭据和撤销。源代码仍采用单管理员，数据关系保留 `owner_id`，没有把设备归属写死到一台电脑。

## 管理员

- 新部署默认 `/setup`，需提供仅保存在服务器数据目录中的初始化验证码。
- WebAuthn 校验挑战、RP ID、HTTPS Origin 和用户验证；挑战绑定发起浏览器或已登录会话，五分钟到期、单次消费。
- 第一次注册仅生成一次 10 个恢复码。恢复码数据库只存哈希，并发使用也只能成功一次；恢复登录撤销旧浏览器会话。
- 已配置密码的部署继续登录，可在设置中添加 Passkey 后关闭密码入口。
- 初始化完成状态持久保存，并发初始化和服务重启都不能重复领取恢复码或重新打开初始化页。

## 设备

- Windows 显示短码；Cloud 登录后核对名称、短码，批准或拒绝。高熵设备码只用于服务和 Cloud 交换，短码不能兑换凭据。
- Windows 和 Gateway 使用独立的设备会话与设备类型校验。旧版 `/api/v1/*` 和 Windows 长配对码协议继续兼容。
- Access Token 为 15 分钟，Refresh Token 为 30 天，均只保存哈希。刷新原子轮换；旧 Token 再次出现或并发重用会撤销该会话并写入审计。
- 设备移除后无法继续访问 Windows 协议或刷新凭据；管理员撤销也会使其网页登录与设备凭据失效。
- Windows 刷新凭据用 DPAPI Machine Scope 存储。配对与后台连接共用凭据锁，避免切换 Cloud 时将新 Token 发送到原 Cloud 地址。
