# Codex Remote 系统对齐（1.15.0）

这轮从原窗口的调用链和数据源入手，修复了 1.14 的历史截断、状态事件丢失和浏览器各自保存项目组织的问题，同时复用参考项目的侧栏、会话、输入、命令、审批和队列组件。版本为 Windows / Cloud / Web `1.15.0`，小程序 `2.1.3`；本轮只更新本机。

## 数据和执行链

```text
网页 / 小程序
  → 已认证的 LanPower Cloud 内存中继
  → Windows Service 的受保护管道
  → 当前登录用户的 Codex Host
  → 原 Codex 窗口的 AppServerManager
```

原窗口模式持续使用该窗口自己的会话、任务、队列和审批通道。Service 不启动 Codex，Cloud 不运行 Codex；网页重连读取实际状态，不重发已经提交的任务。旧的独立运行和备用共享窗口仍兼容，界面按实际连接模式显示控制能力。

## 已对齐的内容

| 领域 | 原来的问题 | 1.15 的行为 |
| --- | --- | --- |
| 完整历史 | 每轮最多 80 条、单项 8000 字；网页最多 128 轮 | 原窗口游标分页，保留完整可见正文、命令输出和条目；不再按上述数量截断。可跳至开头并导出完整 JSON |
| 大内容传输 | 一个响应超出 1 MiB 会断开 | 单帧仍不超过 1 MiB；电脑分段输出、Cloud 按顺序转发、客户端组装；单个结果上限 16 MiB，超限明确失败而不静默裁剪 |
| 实时状态 | 只接受部分通知，忽略原窗口流状态与会话状态 | 接收原窗口 conversation / stream / turn 状态；拥塞时合并历史更新提示，再读取原窗口补齐。日常同步以事件为主，周期检查用于恢复 |
| 服务稳定性 | 中继错误帧或协议拒绝会使整个 Windows 服务退出 | 错误帧、无效数据和连接超时进入重连处理，不让单个远程开发连接故障停止电源服务 |
| 会话设置 | 网页默认模型可能覆盖原窗口模型 | 读取每条会话的模型、思考强度和协作模式；计划模式按原窗口实际支持情况显示 |
| 项目与聊天 | 项目只能作过滤条件，聊天混在单列里 | 以完整根目录区分项目，保留空项目；独立聊天单列；同名不同路径的项目不混合 |
| 收纳与管理 | 浏览器自己的整理状态不能恢复到其他浏览器 | 展开/收起、项目顺序、显示名、收纳、置顶和排序保存在交互用户的 `%LOCALAPPDATA%/LanPower/codex-library.json`；使用版本检查与原子写入 |
| 原生会话管理 | 简化页面缺少一致的入口 | 新建项目聊天、独立聊天、重命名、分支、回退、归档/恢复、完整导出和原生队列操作 |
| 文件与图片 | 指向参考项目本地网址，无法读取被控电脑 | Host 从授权目录读取/搜索文件；图片走认证 RPC，支持原会话引用的本地图片；不把参考项目的中继文件系统作为目标电脑 |
| 能力目录 | 页面没有接入完整能力来源 | 从原窗口读取技能、插件、应用和 MCP；技能发送为原生 skill 输入，MCP 可重新加载；自动化展示这台电脑的授权项目配置 |

图片最大 8 MiB，格式根据文件头验证。目录浏览、文本预览和搜索有独立的结果大小边界；超出范围时页面说明限制。外部图片路径需要来自当前原会话的可见内容，其他会话不能借此读取。正文、审批、图片和队列不写入 Cloud、浏览器存储或日志；项目组织文件只存目录/名称/标识及界面偏好。

2026-10-04 的检查包括：

- Windows 23 项相关自动测试，覆盖原窗口地址约束、审批/队列控制、180 轮历史、长 Unicode 分段、项目状态持久化/冲突、图片路径隔离及无效管道帧后的连接恢复。
- 网页 12 项自动测试，覆盖重连不重发、切换电脑清理未完成分段、历史合并和同名项目归属。
- Cloud 52 项授权、内存中继、远程桌面和版本兼容检查通过；大历史按分段传输，检查中继只保存分段进度，不组装正文，不写数据库。
- 小程序传输兼容检查：长响应组装、授权、重连不重发、会话隔离、引导/暂停和本次审批。
- 浏览器受控接口验证：180 轮对话、1320010 字命令输出的完整导出、项目收纳刷新恢复、本地图片、文件预览、真实 skill 结构、会话模型与计划模式；0 页面错误。
- 原窗口只读实测：用户指定会话返回 3 轮、465 条可见内容，最长命令输出 302272 字；模型、技能、插件、应用和 MCP 接口可用。此项没有发送新推理任务，也没有重启原窗口。
- 安装后复核：Windows 四个组件与最终构建哈希一致，原设备身份、Cloud 地址和项目授权保持；安装版 Host 的原窗口历史与队列读取通过，实际 Service → Cloud → 用户 Host 恢复到 `runtime_ready`。已有真实控制页占用，本轮没有抢占连接或在另一个网页重复提交任务。

上述受控浏览器验证与真实原窗口只读验证分别记录；不把它们当作微信真机、5G 或新的生产服务器验收。1.14 的真实任务/审批记录见 [原窗口整合说明](codex-original-window.md)。

## 仍有差异

2026-10-04 再次按日常工作流程复核，补充了 [实用能力改进清单](codex-remote-improvement-plan.md)，区分已复现的问题、源码确认的限制和待实测场景。后续优先修复状态与事件一致性、未发送的参数选择、草稿与发送确定性、超大历史及控制恢复；继续保留原会话图片和目标电脑目录能力。上文表格和验证记录描述 1.15 的已实现范围，不代表所有边界场景已经完成验收。

当前尚未达到整个参考项目 100% 的功能覆盖：自动化创建/编辑/调度、插件安装与 OAuth、提供商/账号设置、Git 分支/工作树管理、完整终端、文件补丁撤销/重做与语音服务仍由原桌面管理。项目显示名、收纳、排序和置顶属于电脑端的 LanPower 远程组织状态，不直接改写官方桌面的全局状态文件。小程序已经兼容同一大响应协议，界面仍是原生简化页面。

参考项目的一部分辅助页面由中继服务器自己的文件系统或另一套本地 Runtime 提供；复制按钮和页面不能自动获得被控电脑的对应能力。LanPower 对这些操作逐项接到目标电脑，并继续检查原有开发权限、项目授权和审批范围。

## 本机入口与复验

登录 [本机 Codex Remote](https://localhost:8443/remote)。侧栏按项目与独立聊天组织；项目菜单提供收纳、排序和文件入口，会话菜单提供跳至开头及完整导出。

```powershell
cd remote_ui
npm test
npm run build
cd ..
dotnet test windows/LanPower.UnitTests --filter "FullyQualifiedName~Codex|FullyQualifiedName~DesktopCdp"
cloud_app/.venv/Scripts/python.exe -m pytest cloud_app/tests/test_codex_remote.py -q
node tests/test_codex_remote_browser.cjs
node tests/test_codex_system_browser.cjs
node tests/test_mini_program_codex.js
```

本机 Docker 使用独立开发卷、原登录配置和 CA；更新前使用 SQLite backup API 备份并检查。Windows 安装器就地升级，保留设备身份、Cloud 地址、配对和项目授权；不替换原窗口的任务或终止旧备用服务器。远程仓库与正式云服务器需另行明确要求同步。
