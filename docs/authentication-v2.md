# 认证与授权

三种身份分开管理：管理员使用 Passkey 和浏览器会话，Windows/网关使用设备会话，小程序使用客户端会话。Cloud 只保存随机凭据的哈希。

## 管理员

首次 `/setup` 需要服务器初始化验证码。Passkey 注册验证 HTTPS Origin、RP ID、挑战和用户验证；挑战绑定浏览器，5 分钟过期、只能使用一次。首次注册后显示 10 个恢复码，离开页面后不能再次查看。

恢复码使用后立即失效，并撤销旧浏览器会话。进入控制台后可添加新的 Passkey。已有密码部署可保留密码登录；添加 Passkey 后可移除服务器密码环境变量关闭密码入口。

## Windows 与网关

设备发起 `/api/v2/enroll/start`，用户在已登录 Cloud 输入短码并批准。高熵设备码留在设备服务，短码不能兑换凭据。设备通过 `/api/v2/enroll/token` 单次兑换；批准前、拒绝和过期有独立结果。

每台设备有独立 `device_id` 和会话，Windows 凭据不能冒充 Gateway，Gateway 凭据不能访问 Windows 协议。Access Token 15 分钟、Refresh Token 30 天；每次刷新更换两种凭据。旧 Refresh Token 再出现会撤销该会话并写入审计。网页移除设备会撤销其所有会话和未完成命令。

Windows 通过 DPAPI 加密存储凭据；网关使用本地 `0600` 文件。配对和刷新凭据不要复制到另一台设备。

## 手机

管理员在“已授权客户端”中生成一次性二维码，小程序扫描并确认 Cloud 地址后兑换。每台手机单独轮换凭据，可在网页单独移除。客户端访问统一的设备列表和命令接口，不直接调用网关协议。

Cloud 授权与 LAN 配对相互独立。每台电脑的 LAN 凭据只留在 Windows、已配对手机和启用备用控制的网关；不上传 Cloud。旧局域网长期配对码继续兼容。

## 浏览器会话

浏览器使用 Secure、HttpOnly、SameSite Cookie。表单和 JSON 写操作校验 CSRF；客户端 Bearer 请求使用独立验证。页面设置 CSP、防嵌入、HSTS 和禁止缓存；登录与授权入口有限流。

## 授权失败记录

能够匹配现有设备或客户端会话的凭据，在过期、撤销、管理员失效或设备类型不匹配时，会被拒绝并持久记录“设备授权失败”或“客户端授权失败”。刷新失败也按同样规则记录；日志只保存账户、设备编号、事件和时间，不保存提交的凭据或其哈希。

设备按账户与设备、手机客户端按账户合并五分钟内的重复失败。无法匹配现有凭据的请求仍返回未授权，不根据请求中的名称或编号给某个账户创建记录。刷新重用继续独立记录并撤销原会话。

实现细节和历史测试记录见 [统一身份验证记录](unified-identity.md)，使用问题见 [故障排查](troubleshooting.md)。
