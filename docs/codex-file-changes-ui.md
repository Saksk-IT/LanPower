## 正文中的文件链接

小程序原来将 Markdown 链接转换为“名称（路径）”，并在正文下重复显示灰色入口。现在助手正文直接显示蓝色可点击名称，点击“文档已更新”等 Markdown 文件链接，会在当前会话的详情抽屉中渲染文档；正文不再附加路径或重复入口。

文档内的相对链接按当前文档所在目录解析。标题、列表、引用、表格、代码块和行内格式保留，浅深色均可阅读；长文分页，复制完整内容保留原始 Markdown。快速点击或切换会话后，过期读取不能覆盖新详情。ZIP 等其他文件继续进入现有文件查看页，外部地址沿用复制行为。所有文件读取均通过现有项目授权接口。

## 大抽屉内部点击无反应的修复

旧展开处理遇到聊天历史更新锁时直接返回，原生布局查询若迟迟未回调，该锁会持续占用，导致内部思考、网页搜索和文件行点击被丢弃。现在本地展开优先响应，历史加载继续完成；布局查询与渲染等待有超时回退，过期的位置恢复不能覆盖新的点击。

内部按钮改用独立的点击捕获，并通过事件标记携带记录键、操作和文件序号；抽屉本身提供点击接收，点击文字、图标或箭头都能找到对应记录。内部滚动不再吞掉整组触摸事件，外层滚动通过抽屉标记避让。网页搜索也显示折叠箭头，命令仍直接打开完整详情。

## 附件路径混入正文的原因

原生 Codex 为附件附加 `Files mentioned by the user` 说明，包含文件名、临时路径、图片标记及正文边界。实际消息在说明标题前有空行，旧小程序解析要求标题必须位于第一个字符，导致未识别整个说明块，原始说明被直接显示为聊天正文。

网页和小程序现共用附件解析，兼容前置空行、BOM、CRLF、原生多行路径和旧版单行路径。图片在正文上方显示缩略图，文件显示可点击的名称条目；小程序附件靠右排列，正文气泡仅显示实际请求。只有图片、没有文字时不生成空正文气泡；重复图片引用只显示一次。正常正文中的同名标题和不完整说明仍保留，原始消息、附件路径及发送内容不作改写，历史记录刷新后也使用新展示。

## 重复文档入口的原因

旧版小程序从所有消息的原始文字中提取 Markdown 链接，没有区分聊天正文和命令输出。读取 README 后，命令输出里的 `[文档名称](路径)` 也被生成为“↗ 文档名称”，即使命令本身收起仍会出现，重复名称会重复展示。现在仅从用户与助手正文提取聊天链接，命令和工具输出只保留在详情内。
