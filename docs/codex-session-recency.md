# Codex 会话更新时间

版本：Windows / Cloud / Web `1.19.1`，小程序 `3.1.1`。日期：2026-10-04。

## 行为

连接原 Codex 窗口后，点击会话、重复查看、自动刷新、读取历史页和排队消息，均使用只读接口。最近聊天展示原生会话的 `updatedAt`，查看动作不应变成新的会话活动，也不应让旧聊天上移。发送新消息时仍恢复原生线程，再开始新一轮任务。

Host 之前会在每次读取历史时隐式执行 `thread/resume`，读取未加载聊天的队列也会执行恢复。原窗口已有事件监听，这些恢复调用多余且可能触发旧 Runtime 的活动时间更新。现在原窗口读取直接复用既有监听；备用共享连接继续保留它所需的事件订阅。

移除恢复读取后，模型、思考强度和计划模式从原窗口缓存及会话记录的最新上下文中读取，仅转发这三个公开参数。大的工具输出把上下文挤出最近消息范围时，按块向前查找最近设置；不向 Cloud 转发私有指令或原始上下文。

接口约定参考 [OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)：`thread/read` 和 `thread/turns/list` 可读取存储的历史而不恢复线程。当前官方说明也明确恢复本身不应更新活动时间；本修复同时避免在原窗口查看路径调用恢复，以兼容本机正在使用的 Runtime。

真实原窗口只读探针核对两条旧会话，各重复读取历史与队列三次，原生时间与列表顺序保持不变。安装后真实 HTTPS → Cloud → Service → Host → 原窗口网页链路也核对两条旧聊天各点击三次，原生时间、侧栏时间文字和顺序稳定，无写请求，浏览器错误为 0。本轮未提交新的推理任务。
