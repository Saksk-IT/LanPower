# v1.7 升级与使用

Windows、安装器和 Cloud 源码统一为 `1.7.2`，小程序为 `2.0.5`，Wake Gateway 保持 `2.1.2`。本轮在保留数据的前提下更新本机 Docker、Windows 应用和正式 Cloud；Git 主分支已同步，未创建 Release，公开下载入口仍为 v1.6.1。

`1.7.2` 移除设备分组和批量操作，将五个电源按钮直接展示，并将远程桌面改为下载连接文件，提供成功、离线、登录过期和网络失败提示。Windows 与小程序本轮仅同步版本标识。

`1.7.1` 修复 Gateway 续期中断：Cloud 新增仅限 Gateway 类型凭据的 `/api/v2/devices/renew`，长期 Refresh Token 不轮换；Gateway 在响应丢失、重启、`refresh_pending` 或本地写盘失败后可重试。凭据明确过期、撤销或类型不匹配时仍需重新注册。

正常续期会延长授权的 30 天闲置期限，持续在线的网关不会因最初注册的期限耗尽而失效。Gateway `2.1.2` 在新接口明确返回 `404` 或 `405` 时兼容旧 Cloud；旧轮换接口仍禁止在结果不明时重放凭据，续期响应丢失或重启后的完整自动恢复仍待后续网关版本验证。

## 使用新功能

总览自动接收设备状态，每 5 秒检查变化，连接中断后静默重连。浏览器不支持 EventSource 时使用原有轮询。电脑按卡片独立展示，开机、睡眠、休眠、重启和关机直接可见；睡眠、休眠、重启和关机确认后才发送。“已接收”表示云端收到了指令，实际执行结果仍应查看活动记录。

点击开机后，按钮锁定并每 5 秒确认一次在线状态，最多 24 次、约 120 秒。上线时提示成功，3 秒后恢复按钮；未上线时显示检查 Wake-on-LAN 的提示。重新可用的开机按钮仍要求网关在线且唤醒配置可用。

在线且有局域网地址的电脑会显示“远程桌面”和“复制 IP”。点击“远程桌面”下载 `.rdp` 文件，再打开文件并使用目标 Windows 账户登录；网页提供进度和失败反馈。电脑需开启远程桌面，当前网络需能够到达其局域网地址；本功能不提供公网穿透。每次下载使用最新地址，IPv6 地址也支持。

活动记录可按事件类型筛选，每页 50 条，显示关联设备名以及北京时间和相对时间。手机页面折叠导航，并隐藏版本等次要信息。

## 计划任务

在“计划任务”页选择电脑、动作、小时、分钟和星期。所有计划固定使用北京时间（UTC+8）；星期 0 为周日，6 为周六，-1 为每天。工作日计划可分别创建周一至周五五条记录。创建后立即启用，可随时暂停或删除。

服务启动时运行独立调度线程，每分钟扫描一次，所以执行可能比设定时刻晚约一分钟。多个进程通过数据库条件更新领取同一次任务；进程在领取后崩溃时，该次不会重放，防止重复执行电源操作。错过多次计划时，恢复后只尝试一次，然后按当前时间计算下一次；失败同样推进下一次时间，不立即重复发送。任务执行仅表示指令已接收，最终电源结果查活动记录。已撤销的设备或账户不会执行计划。

电脑睡眠、关机或重启可能影响未保存的工作，请按实际使用时间设置。远程开机仍需要已配置并在线的 Wake Gateway；其他电源操作需要可用的控制路径。

## 手机权限

在“手机授权”生成二维码时选择允许的操作，默认全选且至少保留一项。权限随二维码兑换写入手机会话，续期后仍有效。未授权的 Cloud 命令返回 403 并说明受限动作；浏览器管理会话保持完整权限。旧手机会话和升级前生成的二维码默认完整权限，升级不会撤销现有授权。

权限限定 Cloud 命令接口，设备列表和轻量在线查询仍可读取。另行扫码获得的 LAN 配对属于独立授权，不受 Cloud 手机权限约束。要调整已授权手机的范围，请撤销该手机并重新生成二维码。

## 微信离线通知

部署者在私有环境中配置 `WX_APP_ID` 与 `WX_APP_SECRET`；Docker Compose 可写入现有私有 `.env`。两者缺少任何一项时静默禁用发送，计划任务和其他功能仍正常运行。不要将实际密钥提交到仓库。

在“设置 → 离线通知”选择设备，填写接收人的 openid、模板 ID、离线阈值（1–10080 分钟，默认 5）及开关。同设备可设置多个接收人；相同设备、接收人和模板重复保存会更新配置。模板必须包含 `thing1`（设备名称）和 `time2`（最后活跃时间，格式 `YYYY-MM-DD HH:MM`，北京时间）。接收人 openid 必须属于所配置的小程序。

接收人需提前同意微信订阅并有可用额度；一次性订阅额度耗尽后需重新授权，未授权或模板不匹配会发送失败。当前实现提供云端配置及发送能力，小程序尚未新增订阅授权入口，需使用自己的订阅授权流程取得 openid 和额度；仅填写 AppID/Secret 不能保证送达。

每分钟检查超过离线阈值的设备，每条通知配置成功发送后至少间隔一小时。发送失败不影响其他配置，后续扫描会再次尝试；未有心跳的设备以注册时间作为起点。微信 access_token 在单进程内最多缓存约 7000 秒，过期错误会刷新后重试一次。建议以一个 Cloud worker 运行；多 worker 共享通知领取状态，但不共享微信 token 缓存。

## 数据和升级

数据库迁移 `0009_automation` 增加计划任务表、通知配置表，以及手机会话和待兑换二维码的权限字段。现有账户、Passkey、恢复码、设备、网关关系和手机凭据保留。SQLite 连接自动配置 WAL、NORMAL、外键和 10 秒忙等待，多线程可复用连接；非 SQLite 跳过这些参数。

升级前备份原镜像、源码、部署配置和数据库。WAL 模式不能只复制 `platform.db`：运行中应通过 SQLite backup API 获得一致性副本。候选版本先在隔离的备份副本上迁移验证，再停止 Cloud，取切换时快照，保留原生产数据卷启动新镜像。不要将本地测试库覆盖到生产。

原 `1.6.0` 镜像不认识 `0009_automation`，不能直接在已升级数据库上启动。保留实时数据回滚时，应使用经过隔离验证的兼容镜像：以原 `1.6.0` 镜像为基础，仅加入 `0009_automation.py` 迁移文件，其余应用代码保持原样；同时将正式 Compose 的镜像指向该兼容标签，避免后续重建再次使用不兼容镜像。本次已验证兼容镜像能以 UID 10001 启动 HTTP 服务，数据库全部记录不变、初始化入口仍关闭，并保存镜像归档。回滚后新计划与通知不再执行，手机操作权限按旧版完整权限处理。

如需回退数据库结构，先停服务并备份，再使用包含新迁移的程序运行 Alembic downgrade 到 `0008_persistent_clients`。降级会删除新计划、通知和权限设置。应用回滚优先保留实时数据库，不使用升级前快照覆盖新增数据。

Windows 使用 1.7.2 安装器在原安装目录升级，保留 `ProgramData\LanPower` 中的 LAN 配对、Cloud 凭据及网络配置。托盘通过仅回环可用的临时只读凭据读取 `/api/status`，该凭据不能执行电源操作。Cloud 最近通信时间通过 `cloud_last_seen` 返回；只有成功命令轮询能使 `cloud_connected` 为真。
