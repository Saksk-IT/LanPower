# Codex Remote 首屏与重复进入性能

Windows / Cloud / Web `1.24.9`、微信小程序 `3.6.14` 起，Codex Remote 针对 Cloud 和公网中继路径采用分层加载。目标是让用户先看到可用的工作台外壳和最近内容，再在后台补齐完整目录、状态和控制能力；局域网直连路径本轮保持原样，便于继续与电脑端 Codex 的实际体验做比较。

## 加载顺序

1. **Host 先完成连接**：原生 Runtime 初始化后立即发送 `runtime_ready`。项目发现和完整活跃/归档聊天目录不再阻塞连接建立，而是在后台预热。
2. **一次 bootstrap**：支持新协议的 Host 接收 `lanpower/bootstrap`，在一次中继请求中返回快速状态、第一页模型、协作模式、第一页聊天目录，以及路由中带有 `threadId` 时的首屏聊天内容。这样公网路径不再把多个启动请求排成长队。
3. **先展示本地外壳**：网页使用 `sessionStorage`，小程序使用微信本地存储保存设备范围内的项目、最近聊天摘要、选中聊天和目录元数据。缓存不保存聊天正文、轮次、Diff、实时输出、附件、凭据或授权信息，并在 30 分钟后过期。
4. **首屏内容优先**：选中的会话先完成只读 `thread/read` 和最近历史；队列、完整状态、发送回执、能力目录和剩余模型页改为后台读取。快速状态未完成完整登录/权限确认前，控制按钮保持禁用，避免首屏提速改变安全边界。
5. **目录后台预热**：Host 先用原生 `thread/list` 返回第一页并标记 `stale/refreshing`，随后异步建立活跃与归档的完整索引。目录行只读轻量摘要和已存在的状态缓存，不逐条解析聊天历史；选中聊天仍读取真实完整内容。客户端保留旧列表，刷新完成后再替换；搜索会等待完整目录，避免把“暂时没有结果”误显示为“没有聊天”。
6. **小程序返回复用连接**：Codex 页面隐藏、返回首页而卸载时，将连接和内存状态保留 60 秒。重新创建同一账号、Cloud 和电脑的页面时直接复用；切换身份或电脑、超时和授权失效会释放资源。只保留最近一个会话，不把内容写入存储，重新进入后先确认完整状态再开放控制。浏览器刷新无法保留内存连接，因此先从安全外壳缓存绘制，再走 bootstrap 恢复。

## 兼容与边界

- 旧 Host 不支持 `lanpower/bootstrap` 时，网页和小程序自动退回原有分步请求，不需要用户重新配对。
- `lanpower/status {"fast":true}` 只用于首屏快照；完整状态仍会读取原生账号、审批、活动任务和权限信息，并在后台确认后开放控制。
- 只读历史继续使用 Host 的原生快照、`thread/turns/list` 分页和授权检查，不通过恢复会话来“加速”读取，也不把聊天正文写入 Cloud 或浏览器缓存。
- 任务发送、审批决定、队列操作和回执查询仍等待真实 Host 确认；断线不会因为缓存而重发任务。
- 本轮刻意不改 LAN Direct 的连接、缓存或读取时序。本机 Cloud 的局域网 IP 网页入口继续保留：更新 Docker 时必须同时带上已保存的 `dev-network.env` 与 `compose.dev.lan.yml`，保持原 IP 的 8080 监听、允许来源和防火墙范围。公网部署仍需要 HTTPS/WSS、单一 Relay 路由和正常的 Host 在线状态。
- HTTP IP 网页的浏览器不提供 `crypto.randomUUID`，请求编号和发送回执改为共用 UUID 工具，在该环境使用 `getRandomValues` 生成标准 UUID；HTTPS 和 localhost 继续使用原生接口。此项恢复 IP 网页的实际可用性，不调整局域网连接策略。

## 验证范围

本轮完成协议字段校验、Cloud 远程中继 55 项及版本兼容 9 项测试、Web 类型检查与 101 项单元测试、小程序状态 36 项与页面返回重建回归、缓存隔离/脱敏/超时检查，以及 Web 静态资源完整性校验。Windows 整体编译和 145 项单元测试通过。本机真实浏览器分别通过 IP 与 localhost 登录、聊天目录、只读聊天、刷新后的 bootstrap 与完整状态恢复；没有发送真实任务或恢复原生会话。本机更新记录见 [本机开发](local-development.md)；本地部署与模拟页面测试不等同于真实公网或手机验收。
