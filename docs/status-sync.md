# Windows、Cloud 与小程序状态同步

## 状态来源与刷新时间

Cloud 网页和非局域网模式的小程序都读取 `GET /api/v2/devices`。Windows 新服务每 10 秒独立上报心跳，领取命令的长轮询不会阻塞心跳。网页、小程序前台和 Windows 桌面每 5 秒刷新显示；网页重新获得焦点、恢复可见或网络恢复时立即刷新。小程序收到网络切换通知后使旧请求失效，已知蜂窝网络直接查询 Cloud。

| 情况 | 显示与操作 |
| --- | --- |
| Windows Cloud 心跳有效 | 在线，可使用云端直连控制 |
| Cloud 中断，但网关刚确认 Windows 局域网在线 | 在线；只有已授权备用控制时才可通过网关控制 |
| Windows 接受电源动作 | 正在执行电源操作，暂时禁用电源按钮 |
| 服务正常停止且离线上报成功 | 离线；停机前的网关旧观察不能将其重新标为在线 |
| 新版 Windows 心跳超过 35 秒未更新 | 云端直连离线；仍可采用新鲜的网关局域网观察 |
| 网页或手机无法读取 Cloud | 状态未知，关闭远程控制按钮；Wi-Fi 下仍可尝试已配置的局域网唤醒 |

突发断电或断网无法立即上报，通常在最后心跳后约 35～40 秒反映到前台。网关仍使用 75 秒有效期，其较新的局域网观察可独立确认电脑在线。网关的在线判断与备用控制权限分开：知道电脑在线不会自动授权电源操作。未来时间戳不计为有效在线状态。

网页直接更新状态、统计和按钮，保留正在编辑的表单。网络失败后不会继续保留旧的在线状态。小程序切换网络、隐藏页面或更换电脑后，旧响应不能重新启用按钮；网络切换会使尚未确认的旧控制路径失效。蜂窝网络不回退到局域网广播唤醒。

## 协议兼容与连接恢复

新版心跳在原字段基础上增加 `heartbeat_interval: 10`，并支持 `online`、`transitioning` 和 `offline`。Cloud 返回 `presence_protocol: 1`，无需数据库迁移。旧 Windows 心跳仍可使用，按 75 秒失联期限判断。

新版 Windows 遇到旧 Cloud 明确返回 `400 / invalid heartbeat` 时，使用旧心跳格式保持连接；此时退出上报和 35 秒失联判定需要 Cloud 升级后才生效。旧格式响应开始包含 `presence_protocol: 1` 后，Windows 自动恢复扩展上报。

正常停止服务在后台任务停止后，最多等待 3 秒发送离线状态，不撤销设备、不删除凭据。重复电源回执不会覆盖恢复后的在线状态。Windows 在发送回执前等待已发出的旧心跳完成，后续心跳再报告电源过渡状态。睡眠返回、演练或动作失败后重新报告在线，过渡标记本身最多保持 45 秒。

刷新凭据前仍先保存意图标记。明确的 DNS 解析失败发生在请求送达之前，新服务会恢复原标记并自动重试；超时、响应丢失等不确定情况仍要求重新连接，避免重用已消费的刷新凭据。旧版本已留下的不确定刷新标记不能直接删除来强行重试，应通过桌面重新连接 Cloud。

建议先更新 Cloud，再安装 Windows 服务与桌面端，并更新小程序。部署后重新打开网页，使新的状态脚本生效。本次仅提交源码，没有部署到正式 Cloud、替换已安装程序或发布小程序。

## 本地验证（2026-09-30）

- Cloud：97 项测试通过，涵盖浏览器和独立手机授权得到相同状态、新旧心跳过期、恢复、电源回执幂等、网关旧观察失效及控制权限隔离。
- Windows：Release 构建零警告、零错误；53 项单元测试通过，包括长轮询期间继续心跳、旧 Cloud 格式兼容、停止时报告离线并保留授权、DNS 失败重试和不确定刷新禁止重发。
- JavaScript：原版小程序、v2 小程序和网页状态测试均通过，覆盖蜂窝网络、Wi-Fi 切换、过期响应、失败恢复、页面隐藏和按钮状态。CI 增加网页状态脚本测试。
- 隔离服务以 `--dry-run` 启动：LAN 授权、状态、二维码、动作白名单、202 回应、操作间隔与演练执行通过。未发送真实电源操作，未通过生产命名管道执行写操作。
- 浏览器使用隔离数据库及已有 Playwright（Browser 插件不可用），验证总览、我的设备和网关页；1280×900 与 390×844 下状态自动变化、断网时未知、恢复后在线、未保存名称保留均通过，无页面运行错误及手机横向溢出。断网演练预期产生一条网络错误。
