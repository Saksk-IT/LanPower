# 网页 Codex 权限切换（1.20.0）

在 Codex Remote 选中电脑和会话后，点击输入框下方、加号旁的权限按钮。菜单沿用原生桌面的三个模式，勾选当前实际生效的模式，完全访问以橙色显示；窄屏将权限与模型参数分成两行，支持深色和 Escape 关闭。

| 模式 | 行为 |
| --- | --- |
| 请求批准 | 允许工作区内的常规操作，访问互联网或修改工作区外文件时请求用户批准 |
| 帮我批准 | 保留工作区沙盒，交给 Codex 原生审核器评估符合条件的审批请求；需要人工处理的风险操作仍通过原生审批流程处理 |
| 完全访问权限 | 使用原生完整访问模式，取消 Codex 沙盒的文件与网络边界，并关闭操作审批提示 |

更改用于当前会话的后续任务。当前正在执行的任务、已经发起的审批及子会话保留各自设置；网页会明确提示生效范围。选择模式不会发送任务、停止任务、自动回复现有审批或修改全局配置。原生管理规则仍可拒绝请求，失败会显示原因，不会提前把按钮改成成功状态。

## 原生状态与兼容

权限状态来自电脑端原生会话设置及 `thread/settings/updated.threadSettings`，同时读取审批策略、审核器、沙盒和命名权限配置。原窗口接入还只读获取桌面缓存的 `latestThreadSettings` 和 `currentPermissions`，只传输权限字段，并以当前有效权限为准，不恢复会话或改变查看时间。外部修改会同步回网页，刷新与切换会话重新读取；自定义配置显示“自定义权限”，字段缺失和断线显示“权限未提供”，不会猜测成完全访问。

Cloud 与 Windows 的白名单新增 `lanpower/permissions/set`，只接受会话标识与三个固定模式。Host 核对已有开发权限和项目范围后转换为原生 `thread/settings/update`，通过原生有效设置通知确认结果。新建空会话尚未生成历史记录，也能切换权限。共享会话发送新任务时沿用原生权限，不再强制覆盖为请求批准。Cloud 仅中转请求并记录权限更改请求的审计事件，不保存会话设置或正文。

需要 Windows / Cloud / Web `1.20.0`，并连接原 Codex 窗口或备用共享窗口。旧电脑端、独立执行模式或原生接口不支持时明确提示，不能用网页按钮伪造支持。小程序版本同步为 `3.1.2`；本次新增权限菜单在网页，小程序保留原有界面。

原生行为依据 [OpenAI 权限与沙盒说明](https://learn.chatgpt.com/docs/sandboxing)；接口字段以本机 Codex 导出的实验协议为准，审批与沙盒的会话覆盖机制见 [App Server 文档](https://learn.chatgpt.com/docs/app-server)。

## 验证

已通过网页 88 项单元测试、Cloud 58 项相关检查及 Windows 21 项会话与协议测试。检查覆盖固定模式与额外参数拒绝、项目范围、原生拒绝、空会话、运行中任务保留、下一任务继承权限，以及桌面缓存读取的权限优先级与私有设置过滤。真实 Codex 的临时会话已验证三个原生模式，未发送推理任务。

浏览器验收入口为 `tests/test_codex_permissions_browser.cjs`，用实际构建页面和隔离 RPC 验证菜单、切换、刷新恢复、外部设置通知、会话隔离、错误和旧版本提示，以及 1440/390/320px 浅色与深色布局。受控浏览器检查与真实原生临时会话检查分别记录，不替代用户正在使用的桌面会话、微信真机或 5G 验收。

本机 Docker 与 Windows 安装后，真实 HTTPS 链路只读确认原窗口的当前权限和菜单可用状态；两条旧会话各读取三次，时间、标签和排序稳定，真实网页写请求和页面错误为 0。本轮未修改用户已有会话权限。部署与数据保留记录见 [本机开发环境](local-development.md)。
