# Codex Remote 深度审查与后续优化建议

审查日期：2026-10-04；浏览器末次复核为本地时间 15:49，源码补充核对至 15:56。参考项目提交：`codex-remote-bridge` 的 `1bbcf5a`。LanPower 已提交核心基线为 `6cd805a`（1.16.0）；本轮也检查了工作区的 1.16.1 会话展示及继续开发中的小程序、多页面连接模块。本机 `/healthz` 返回 Cloud `1.16.1`，受控浏览器检查使用本机已提供的网页资源。

本轮交付审查和建议，不修改运行时代码。工作区有其他开发改动，本文中的“已复现”对应本次检查快照；后续修复通过相应回归后再关闭事项。Windows 安装更新、微信真机和正式云端部署不作为本轮验证结果。

## 审查结论

原窗口接入、网页任务状态、参数选择、草稿、发送回执、大历史传输与原生控制已经有实现基础。此前 1.15 的五项 P0 改进及验收记录见 [P0 实现与验收](codex-remote-p0.md)，不再把那些初始问题当作尚未实现的能力。

当前主要差距集中在：复杂历史场景的操作正确性、消息类型覆盖、项目与聊天的全量管理、文件输入与成果交付、Git 审阅、跨端能力及版本契约。本轮还发现了新的边界问题，需要先修复，再扩展更多功能。

继续保留原会话图片、目标电脑的真实目录浏览、原生会话控制、电脑端项目收纳与既有授权。这些已经形成 LanPower 的实际优势。参考项目的界面和流程可以复用；各项文件、Git、终端、账号和自动化操作，需要分别确认它们使用的是目标电脑还是中继服务器。

## 逐层核对

1. **接入与执行来源**：核对 Cloud → Service → 交互用户 Host → 原窗口的调用链、方法白名单、审批与队列、大小边界及能力标识。
2. **会话操作与内容**：核对分页、分支/回退、公开工具条目、图片、参数和发送回执；用受控浏览器检查实际请求与显示。
3. **项目与文件**：核对全量搜索、置顶、归档同步、嵌套项目归属、目录/编码、上传下载及 Git 操作入口。
4. **其他能力与小程序**：核对参考项目的自动化、插件/应用、提示模板、额度、终端等实际后端，以及小程序页面和新增模块是否接入。
5. **异常与验证边界**：核对多个大项同时出现、缓存淘汰、输入校验、混合版本、单控制页限制与真实设备验收。

## 首批需要修复的问题

### R1：同页多个大项会产生已经失效的引用（P0，已复现）

**证据：** 用实际 `RemoteHistoryStore.cs` 编译隔离程序，并用实际 `DesktopRenderer.js` 在隔离的原窗口管理器中测试。一个轮次包含两个各 17 MiB 的文本项；缓存按 UTF-16 占用限制为 64 MiB。打包第二项时第一项被淘汰，但返回的页面仍含第一项的引用。连续重新打包 3 次，第一项每次在首次读取前就已失效，第二项均可读取。

**影响：** 单个 17 MiB 内容可通过验收，不代表多个大项同时可用。网页遇到失效引用后刷新该轮再读，可能重复取得同样失效的引用。缓存失效已实际复现；整页持续重试的行为由恢复代码推断，未触发真实原窗口大任务。

**建议：** 给返回中的引用建立有效期和读取租约，按缓存预算决定一页可发布的引用；支持按项获取或流式读取，避免返回时已经失效。缓存压力和过期恢复有明确重试次数与退出条件，继续保持有界内存。

**验收：** 同一轮两个大项、跨轮多个大项、背景刷新与前台读取并发、取消及过期恢复；所有发布的引用首次读取有效，不发生永久重试。不能仅以提高缓存上限关闭此项。

代码：[历史缓存](../windows/LanPower.CodexHost/RemoteHistoryStore.cs)、[原窗口适配器](../windows/LanPower.CodexHost/DesktopRenderer.js)、[历史恢复](../remote_ui/src/LanPowerApp.vue) 的 `restoreContent`。

### R2：在旧历史页分支/回退时定位不准确（P0，已复现）

**证据：** 受控 180 轮会话跳到开头，最后一页包含第 1～4 轮。从第一轮回复分支，网页按当前页长度发送 `numTurns: 3`，分支保留 177 轮，目标应是保留 1 轮。回退第一轮时发送 `numTurns: 4`，只移除最后 4 轮，目标应是移除 180 轮。

**根因：** `forkThread` 和 `rollback` 使用当前加载窗口的长度与下标计算原会话的尾部轮数；分页窗口的下标并不代表原窗口的全局位置。

**小程序源码复核：** 新控制模块已禁止在开头窗口中回退，但从某一轮分支仍按局部窗口计算尾部数量，缺少同等保护。该项为源码确认，未做微信真机复现。

**建议：** 使用稳定的原生轮次标识定位，电脑端在操作前核对目标轮次、尾部轮数及历史版本；遇到并发新任务或位置变化时明确拒绝。尚不能准确定位时关闭对应旧页操作，并说明原因。

**验收：** 180 轮的开头、中间、末尾；普通“加载更早”和开头窗口模式；操作前桌面新增轮次；失败后正确恢复阅读位置。回退仍明确说明已有文件修改保留。

代码：[会话操作](../remote_ui/src/LanPowerApp.vue) 的 `forkThread` / `rollback`、[消息轮次索引](../remote_ui/src/api/normalizers/v2.ts)、[小程序控制模块](../mini_program/utils/codex/controller.js) 的 `threadAction`。

### R3：输入校验错误被当作发送结果不确定（P0，已复现）

**证据：** 网页可以发送 16001 个 ASCII 字符。实际 Cloud 校验函数拒绝该输入；受控网页收到同样的不含 RPC 编号的错误帧后，原请求仍等待超时，随后显示“结果待确认”。本次将原代码 35 秒超时缩短为 1.5 秒验证状态，未测真实等待时长，也未向原窗口派发。

**建议：** 前端在清空草稿前校验最终发送内容，包含文件引用前缀、图片总量及技能数量；已识别请求的参数错误用对应 RPC 编号返回，并明确“未发送”。统一 Python / C# / JavaScript 对 Unicode 长度与字节的计量规则。

**相关边界：** 实际协议允许最多 4 张图片、图片 URL 合计 850000 字符；输入组件没有完整对应的合计校验。队列读取支持全部分页，但重排协议最多 32 条，33 条重排已被实际校验函数拒绝。

新小程序控制模块已经在提交前校验文本与文件引用合计、图片和技能数量，可将该行为作为网页对齐依据；Unicode 计量和 Cloud 错误归属仍需统一。

**验收：** 文本边界、中文/emoji、附加文件引用后超限、多图合计、33 条队列；失败立即反馈并保留草稿，不误记成原窗口可能已经接受。

代码：[输入组件](../remote_ui/src/components/content/ThreadComposer.vue)、[发送与回执](../remote_ui/src/LanPowerApp.vue)、[Web 连接](../remote_ui/src/lanpower/connection.ts)、[Cloud 协议](../cloud_app/app/remote.py)、[Windows 协议](../windows/LanPower.Shared/CodexRemoteProtocol.cs)。

### R4：工具条目已有兜底，专门展示与类型验收仍需完善（P1，部分改善已验证）

**证据：** 15:49 在本机实际页面展开工作过程及详情后，合成的 MCP 结果和搜索条目均可看到。`toolResult` 已提供安全详情兜底，不能认定这些条目仍被静默丢弃。当前主要采用公开原始数据详情，未知类型也有入口；参考项目自身亦有部分类型覆盖不足。

**建议：** 为 MCP、搜索、动态工具、协作任务、上下文整理等当前原生类型逐项建立公开信息映射，显示调用对象、输入摘要、结果与错误状态；保留未知类型的安全折叠详情和版本提示。上下文整理只显示公开提示；继续剔除隐藏/加密推理。

**验收：** 每种类型覆盖进行中、成功、失败和重连后的历史；从原窗口逐项核对公开可见内容，防止“传输完整但页面忽略”。

代码：[历史保留](../windows/LanPower.CodexHost/RemoteHistory.cs)、[消息转换](../remote_ui/src/api/normalizers/v2.ts)、[会话组件](../remote_ui/src/components/content/ThreadConversation.vue)。

### R5：聊天库的完整性和同步仍不足（P1，部分已复现）

**证据：** 受控浏览器确认搜索不会继续查询未加载会话、未加载的置顶会话不出现、刷新列表后桌面已归档的条目仍残留。源码另确认 Host 的项目归属优先选较短根目录，与网页后备逻辑的最长目录匹配不一致。

**建议：** 目标电脑维护授权会话的搜索/置顶元数据，按查询分页；归档、恢复、重命名与新会话用增量事件和可靠校验更新。嵌套项目统一规范化路径和最长根目录匹配。保持当前展开/收纳状态及选中会话可见。

**验收：** 超过 50 条的搜索、刷新后旧置顶、桌面归档/恢复、同名及嵌套项目、多浏览器整理。不能直接删除首屏未返回的所有条目，否则会误删分页缓存中的旧会话。

代码：[聊天库](../remote_ui/src/lanpower/library.ts)、[列表读取](../remote_ui/src/LanPowerApp.vue)、[Host 项目归属](../windows/LanPower.CodexHost/RemoteRuntime.cs) 的 `Summary`。

### R6：图片缓存与显示组件的生命周期不一致（P1，已复现）

**证据：** 用实际 Vue 图片组件和缓存模块显示一张合成图，再读取另外 32 张。第 33 张触发缓存淘汰，最早的对象地址被撤销，但原组件仍保存该地址；点击放大时发出旧地址，预览加载失败。再次调用缓存解析可以恢复，组件当前的点击路径没有执行这一步。

**建议：** 给仍显示中的图片建立引用管理，或在缓存代际变化、重连和点击时重新解析；提供进度、失败重试、原图下载。输入图片目前固定转为 JPEG，需要明确处理透明图、动画和原图保真需求。

**验收：** 33 张及以上、多张大图触发字节预算、断线重连、返回早先图片、原图下载；不重建整个会话也能恢复预览。

代码：[图片缓存](../remote_ui/src/lanpower/images.ts)、[图片组件](../remote_ui/src/components/content/RemoteMessageImage.vue)、[输入图片处理](../remote_ui/src/api/codexGateway.ts)。

## 系统层面的改进方式

- **统一操作与数据契约**：按稳定的电脑、会话、轮次、条目标识传递操作意图；页面下标只用于显示。历史快照、任务版本、资源引用与提交回执各自有清楚的有效期。
- **协议集中维护**：Cloud、Windows、Renderer、Web 和小程序的白名单、长度与能力定义形成可生成或可交叉校验的契约；补混合版本、Unicode 和错误归属测试。
- **共享行为，保留原生界面**：提炼状态机、参数、草稿、回执及分页行为，减少两个客户端各写一份后产生差异。网页与微信分别保留适合各自平台的展示层。
- **按功能管理成熟度**：记录“可读取、可操作、可恢复、已真机验收”，区分设计限制、尚未接入、已经失效；版本记录不以页面出现入口作为完成功能。
- **把资源交付作为完整流程**：目录、聊天附件、生成文件、预览与下载使用统一的目标电脑资源标识、授权及生命周期。Cloud 继续作为有界内存中继。
- **保持升级路径可维护**：原窗口适配属于内部接口整合，启动时检查所需能力；保留上游来源和组件修改记录，用行为回归评估更新。Git/文件/终端的辅助实现分别核对机器来源。
