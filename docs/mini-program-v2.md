# 小程序 v2：独立授权与设备控制

## 使用

1. 在 Cloud 网页的“已授权客户端”中填写手机名称，生成一次性二维码。
2. 在小程序“我的电脑”或“连接”扫描授权二维码，确认 Cloud 地址后连接。二维码十分钟有效、只能兑换一次；重新生成会取消之前未使用的二维码。
3. 在“我的电脑”选择目标。在线且控制通道可用时，可以睡眠、休眠、重启、关机；在外远程开机可先在新版 Windows 应用点击“配置远程唤醒”，网页选择网关后自动配置。首次配置时电脑与网关需在同一局域网保持在线。按钮说明显示当前不可用的原因。
4. 要使用局域网优先，到“连接”为当前选中电脑扫描 Windows 应用“手机配对”中的二维码，并核对电脑名称。不同电脑的局域网凭据分别保存在手机本地。手机需要连接与电脑同一局域网的 Wi-Fi，电脑也可使用网线。
5. 展开“局域网唤醒设置”，手动填写并保存 MAC 与广播地址。二维码不含唤醒参数，Cloud 不接收局域网配对凭据。后台刷新与切换电脑不会覆盖尚未保存的草稿。
6. “帮助”提供远程控制、局域网与开机/唤醒的分步骤指引，以及可展开的离线、睡眠/休眠、授权失效说明。

原有局域网与 v1 远程功能保留在“独立局域网 / 旧版连接”入口，原存储键和接口保留。独立模式无需 Cloud，可在页面上配置并保存唤醒参数，未配置时不会使用示例 MAC 唤醒。主入口 v2 缓存已选择电脑及列表，因此重启小程序后 Cloud 故障也可以继续尝试已配对电脑的局域网控制。右上角刷新与下拉刷新会更新 Cloud 列表，以发现新电脑。

小程序应用版本为 `2.0.2`，协议版本为 `2`，“帮助”底部显示应用版本。本次修复手机长期授权与自动续期。Cloud 的客户端页面显示授权时上报的版本。

## 身份与协议

- `POST /api/v2/clients/enroll` 接收一次性 `code` 及 `version: "2.0.2"`、`protocol_version: "2"`，返回该手机独立的 `client_id`、Access Token、Refresh Token 和过期时间。旧版仅提交 `code` 仍可使用；新客户端仅在旧 Cloud 明确拒绝额外字段且未消费授权码时重试旧格式，网络超时或结果不确定时不重试兑换。
- Access Token 十五分钟，手机 Refresh Token 为长期授权，持续有效直到手机或管理员被撤销；Cloud 只保存哈希，手机凭据只保存在本机。新会话的 `refresh_expires_at` 为 `NULL`，长时间不用不会自动过期。
- `POST /api/v2/clients/renew` 接收 `client_id`、`refresh_token`，仅更新 Access Token，保留 Refresh Token。小程序合并并发续期；响应丢失、存储失败或重启后可以再次续期。网络错误、5xx、429 或无效响应均保留授权，下一次刷新重试；只有明确的 401 才显示重新扫码。
- 旧 `/api/v2/clients/token` 继续为旧客户端提供单次轮换及重用撤销保护。新版只使用 `/renew`；旧 Cloud 返回 404/405 时提示升级，不回退到单次轮换接口，避免在响应丢失后误撤销。Windows、Gateway 的设备凭据策略独立。
- 客户端调用 `GET /api/v2/devices`、`GET /api/v2/devices/{id}`、`POST /api/v2/devices/{id}/commands` 和 `GET /api/v2/commands/{id}`。请求中不需要网关编号。
- 浏览器的写请求继续检查 CSRF；客户端使用独立授权头。设备凭据不能访问客户端接口，客户端凭据不能冒充 Windows。
- Cloud 页面可以逐个移除手机；手机“撤销这部手机的授权”调用 `POST /api/v2/clients/revoke` 撤销自身。授权失效时显示重新扫码入口，允许移除本机失效授权；已关联的局域网仍可尝试控制。重新授权后可在网页移除旧记录。
- 局域网状态可达时直接控制，否则请求 Cloud。电源请求已经发出却未收到确认时，不会自动改走另一条路径重复执行。Cloud 接收命令后，小程序继续查询执行结果，区分接收与送达。

## 长期授权升级

1. 先备份并保留正式 Cloud 数据，更新 Cloud 至 `1.5.1`。启动迁移 `0008_persistent_clients` 将未撤销手机的刷新期限改为长期，保留手机编号、凭据哈希、历史与撤销状态；过期但未撤销的旧授权也可继续使用。不要用测试数据库覆盖正式数据。
2. 再更新小程序至 `2.0.2`。旧版本在刷新中断后留下的 `refresh_pending` 标记不再阻止连接；如果手机还持有云端当前凭据，会自动恢复并清除标记。
3. 若旧 Cloud 已消费手机保存的旧凭据，而手机没收到新的，或会话已经被撤销，更新无法恢复已作废密钥。此时在 Cloud 生成新码再扫码一次。清除小程序数据、换手机或管理员撤销也需要重新授权。

旧问题由三处叠加导致：短期 Access Token 到期后需要续期；单次轮换的响应丢失会使新凭据无法恢复；小程序把所有刷新失败都转为重新授权并永久保留失败 Promise/标记。旧手机凭据另有 30 天闲置限制。新版把临时网络故障和真实授权失效分开，长期凭据可重复换取短期访问权。
