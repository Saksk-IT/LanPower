# Codex 原生额度、上下文与能力状态

Windows / Cloud / Web `1.19.0` 与小程序 `3.1.0` 共用同一套原生状态规则。网页和小程序只读取选中电脑的 Codex 原生接口；Cloud 只在已有认证的 WSS 中继中转数据，不保存额度、上下文或能力目录。

## 额度与上下文

- 额度来自 `account/rateLimits/read` 及 `account/rateLimits/updated`。每个原生额度桶单独显示窗口、实际 `usedPercent`、重置时间和原生积分字段；有效的 `0` 会保留，缺失百分比、余额或窗口不会补成估算值。
- 当前聊天的上下文来自 `thread/tokenUsage/updated`。显示原生的当前 token、累计 token、`modelContextWindow` 和由这两个原生数值计算的剩余比例；接口没有上下文窗口时只显示实际 token，并说明无法计算比例。页面不再使用固定上下文基线。
- 读取失败、字段不完整、断线、切换电脑或旧请求晚到时，清除旧的可用数值并显示原生错误或原因。没有原生数据时不会显示“可用”、零余额或推测额度。

## 能力目录

技能、插件、应用和 MCP 服务沿用原窗口目录。网页和小程序都显示四类状态：`已安装`、`未启用`、`需授权` 和 `未知`；只有原生明确返回的字段才会改变状态。缺少 `installed`、`enabled`、访问权或 MCP 认证字段时保留“未知”，不会用工具数量、名称或描述推断授权。

每次只读取一页 24 项。应用和 MCP 使用原生游标；技能和插件在交互用户的 Windows Host 中读取一次原生目录后生成有界的短期快照，再用不透明游标返回页面。Cloud 不接收 `cwd` 以外的目录权限参数，也不把页面参数转发给 Codex 原生接口。快照按授权项目范围隔离，最多保留四份、两分钟，手动刷新会重新读取原生目录；过期或变化的游标提示刷新。

旧版电脑端没有能力分页标志时，网页和小程序会明确提示“电脑端未提供目录分页，请更新电脑端和 Cloud 后重连”，不会读完整目录后假装分页。原生目录失败、市场未授权或摘要预算超限也显示接口返回的原因。

## 验证边界

本轮完成了网页 84 项单元测试、隔离 WSS 页面检查（额度成功/失败、上下文、24 项分页、四类状态、断线及无写操作）、小程序原生状态和 320/390/430px 编译布局检查、Cloud 237 项测试、Windows 103 项测试，以及 `1.19.0` 安装包构建。浏览器目录检查使用受控 RPC 夹具，不把夹具数据当作真实 Codex 额度；随后又通过本机实际 Windows Host 的认证 WSS 做了只读额度和能力目录检查，没有点击安装、授权、发送或其他写操作。本机 Windows 安装后的身份、Cloud 地址、Service/Desktop/Host 运行状态也已通过只读检查。微信真机、物理休眠、5G 和正式 Cloud 仍按项目验收边界由人工执行。
