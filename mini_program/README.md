小程序主入口是 Cloud v2，底部导航分为四个区域：

- **我的电脑**：选择 Windows 电脑、查看状态和执行电源操作。“开机 / 唤醒”单独展示，不可用时说明原因。右上角刷新和下拉刷新都会更新 Cloud 电脑列表，即使当前正在使用局域网直连，也能发现新电脑。
- **Codex**：选择开发电脑、浏览项目与会话；在消息详情继续任务并处理审批。外观可跟随系统、使用浅色或深色。
- **连接**：管理 Cloud 手机授权、可选的局域网直连，以及局域网唤醒的 MAC 和广播地址。
- **帮助**：按“远程控制 / 局域网 / 开机与唤醒”查看步骤，展开常见问题；底部可查看小程序版本。

## 第一次使用

1. 在 Windows 应用中先完成 Cloud 配对，让电脑出现在 Cloud 网页的设备列表中。
2. 在 Cloud 网页进入“已授权客户端”，为这部手机生成一次性二维码。
3. 在小程序的“我的电脑”或“连接”页点“扫描 Cloud 授权码”，确认授权后选择电脑。
4. 在家中需要直连时，进入“连接”页扫描当前电脑的局域网配对码。二维码位于 Windows 版 LanPower 的“手机配对 → 显示配对二维码”。局域网凭据按电脑分别保存在手机，不上传 Cloud。
5. 需要局域网离线开机时，展开“局域网唤醒设置”，手动填写并保存 MAC 与广播地址。配对码只含连接地址和凭据，不会自动带入唤醒参数。MAC 可在 Windows 版 LanPower 首页的“网络与唤醒”查看。

Cloud 授权和局域网配对是两项独立配置。撤销手机授权后，需要重新授权才能访问电脑列表；已保存的局域网关联会在重新授权同一 Cloud 后继续使用。移除局域网关联需要确认，不影响手机远程授权。

使用小程序 3.0 的 Codex 控制时，Cloud 与 Windows 建议同步更新至 `1.20.0`。在 Cloud「手机授权 → 修改手机权限」中勾选 **Codex Remote 远程开发** 并保存，已有手机无需重新扫码；新手机在生成二维码前勾选此权限。原来只用于电源的授权不会自动获得开发权限。在 Windows LanPower 中开启 Codex Remote 并保存项目授权，随后点击小程序底部 **Codex**。新版原窗口支持网页与小程序同时控制；旧运行模式根据实际能力显示只读与交还桌面。

Cloud `1.5.1` 与小程序 `2.0.2` 支持一次扫码长期授权。短期访问凭据自动续期，断网、超时、退出微信或长期未打开都不会使手机授权到期。先更新 Cloud，再重新编译或上传新版小程序；旧平台会显示更新提示并保留手机凭据。旧版已撤销授权或已轮换但丢失新凭据时仍需最后扫码一次，不能恢复已作废的密钥；详见 [长期授权升级](../docs/mini-program-v2.md#长期授权升级)。

授权后没有电脑时，首页会提示在 Windows 应用连接同一个 Cloud。输入中的唤醒参数不会被后台状态刷新覆盖，切换电脑再切回也会保留草稿；只有点击“保存”才写入手机存储，退出小程序后未保存的草稿不保留。

## 按状态操作

- **在线且控制通道可用**：睡眠、休眠、重启和关机可用；已在线时无需唤醒。
- **离线**：有可用唤醒方式时，才可尝试“开机 / 唤醒”。在家中 Wi-Fi 下需要局域网配对及有效的唤醒参数；在外唤醒可先在新版 Windows 应用点击“配置远程唤醒”，网页选择网关后自动配置，无需手填 MAC 或广播地址。首次配置时电脑与网关需在同一局域网保持在线。网关未配置、离线等原因会显示在按钮说明中。
- **正在执行电源操作**：先等待状态同步完成，不要重复发送同一动作。
- **状态未知**：先检查网络并刷新；如果已保存局域网唤醒参数且手机仍在 Wi-Fi 下，可尝试局域网唤醒。
- **手机授权需要更新**：仅 Cloud 明确拒绝授权时显示；在 Cloud 网页重新生成二维码后扫码。普通网络故障显示暂时无法连接并自动重试，已关联电脑的局域网直连仍可尝试使用。

电源指令会在手机上再次确认。页面每五秒检查一次状态；“唤醒包已发出”“指令已送达”都不代表电脑已开机，应等待电脑上线。电脑需事先启用网络唤醒，保持供电和网线连接。

## 只使用局域网，或继续使用旧版配对

首页的“只在家中使用？”和“连接”中的“独立局域网 / 旧版连接”都可进入独立模式。扫描电脑配对码即可直接控制，无需 Cloud；需要唤醒时，在本页填写并保存 MAC 与广播地址。未配置真实唤醒参数时，不会向代码中的示例 MAC 发送唤醒包。

此入口继续读取 `lanpower_pairing_v1` 和 `lanpower_remote_v1`，兼容 v1 Cloud/网关远程配对。Cloud v2 手机授权码应在主入口扫描。v1 与 v2 的局域网设置分别保存，互不覆盖。

## 在 iPhone 上预览

1. 仓库中的 `project.config.json` 使用公开占位值 `touristappid`。在本机微信开发者工具里设置自己的小程序或测试号 AppID；提交前保留公开占位值，不提交个人配置。`project.private.config.json` 已被 Git 忽略，项目没有使用或保存 AppSecret。
2. 在微信开发者工具中导入此目录，编译后点“预览”，用 iPhone 微信扫描开发者工具给出的二维码。
3. 在微信公众平台配置 Cloud 的 HTTPS `request` 合法域名；Codex 还需要同一 Cloud 的 WSS `socket` 合法域名。开发者工具的本地调试选项不能替代真机域名配置。当前本机 `https://localhost:8443` 仅供电脑测试，手机无法通过自己的 localhost 访问电脑。
4. 局域网直连时，让 iPhone 连接与电脑同一局域网的 Wi-Fi，电脑可通过网线连接路由器；首次弹出微信本地网络访问提示时选择允许。

## 页面注册与开发检查

`app.json` 注册的三个页面均包含 `.js`、`.json`、`.wxml`、`.wxss`，并启用 `theme.json` 与系统深色模式。请完整导入 `mini_program` 目录；遇到“页面 JSON 文件缺失”时确认 `pages/cloud/cloud.json`、`pages/index/index.json` 和 `pages/codex/codex.json` 存在，再重新编译。忽略与公开文件检查规则只对这一份页面 `cloud.json` 放行，运行时私有 Cloud 配置仍禁止提交。

项目使用微信 `style: v2`，原生普通按钮默认固定为 `184px`，会覆盖单个类选择器声明的宽度。`app.wxss` 用 `button.类名` 统一设置整行按钮的 `width: 100%`、边框盒和水平外边距，让首页局域网入口、连接页旧版入口、FAQ、扫码及电源按钮填满各自容器；刷新、关闭和导航按钮按各自布局保留尺寸。新增按钮时复用相应样式类，布局检查需包含微信 v2 默认规则，并核对按钮实际宽度与容器宽度，不能只检查横向溢出。

从仓库根目录运行：

```powershell
node tests/test_mini_program.js
node tests/test_mini_program_v2.js
node tests/test_mini_program_codex.js
node tests/test_mini_program_environments.js
```

前三项检查分别覆盖旧版兼容、电源与长期授权、Codex 的长连接恢复及交互。Codex 检查包含只读桌面会话、恢复后发送、补充要求、暂停、审批防重复提交、断线不重发、旧连接隔离及安全富文本。另有 `tests/test_mini_program_codex_layout.cjs` 使用本机微信 WCC/WCSC 编译结果和浏览器 DOM 适配器，检查 320/390/430px、深色、审批及键盘布局；运行需配置微信编译器与 Playwright。此检查不代表微信真机验收。电源验证记录见 [小程序 v2](../docs/mini-program-v2.md)。

小程序版本为 `3.1.2`、协议版本为 `2`；保留手机长期授权与自动续期。Codex 消息、代码、Diff 和审批内容仅保存在页面内存，退出页面关闭手机控制连接；已有任务仍由电脑运行，重新进入读取实际状态。项目不包含真实 Cloud 域名、LAN Token、Gateway 凭据或远程配对二维码。

本轮 Codex Remote 系统对齐见 [1.15 系统说明](../docs/codex-system-parity.md)：完整历史分段传输、原窗口状态与模型同步、电脑端项目/聊天组织、文件图片及能力目录。小程序保持原生简化界面，已支持同一大响应协议。
