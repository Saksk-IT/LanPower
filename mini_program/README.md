# LanPower 微信小程序

小程序主入口是 Cloud v2，底部导航分为三个区域：

- **我的电脑**：选择 Windows 电脑、查看状态和执行电源操作。“开机 / 唤醒”单独展示，不可用时说明原因。右上角刷新和下拉刷新都会更新 Cloud 电脑列表，即使当前正在使用局域网直连，也能发现新电脑。
- **连接**：管理 Cloud 手机授权、可选的局域网直连，以及局域网唤醒的 MAC 和广播地址。
- **帮助**：按“远程控制 / 局域网 / 开机与唤醒”查看步骤，展开常见问题；底部可查看小程序版本。

## 第一次使用

1. 在 Windows 应用中先完成 Cloud 配对，让电脑出现在 Cloud 网页的设备列表中。
2. 在 Cloud 网页进入“已授权客户端”，为这部手机生成一次性二维码。
3. 在小程序的“我的电脑”或“连接”页点“扫描 Cloud 授权码”，确认授权后选择电脑。
4. 在家中需要直连时，进入“连接”页扫描当前电脑的局域网配对码。二维码位于 Windows 版 LanPower 的“手机配对 → 显示配对二维码”。局域网凭据按电脑分别保存在手机，不上传 Cloud。
5. 需要局域网离线开机时，展开“局域网唤醒设置”，手动填写并保存 MAC 与广播地址。配对码只含连接地址和凭据，不会自动带入唤醒参数。MAC 可在 Windows 版 LanPower 首页的“网络与唤醒”查看。

Cloud 授权和局域网配对是两项独立配置。撤销手机授权后，需要重新授权才能访问电脑列表；已保存的局域网关联会在重新授权同一 Cloud 后继续使用。移除局域网关联需要确认，不影响手机远程授权。

授权后没有电脑时，首页会提示在 Windows 应用连接同一个 Cloud。输入中的唤醒参数不会被后台状态刷新覆盖，切换电脑再切回也会保留草稿；只有点击“保存”才写入手机存储，退出小程序后未保存的草稿不保留。

## 按状态操作

- **在线且控制通道可用**：睡眠、休眠、重启和关机可用；已在线时无需唤醒。
- **离线**：有可用唤醒方式时，才可尝试“开机 / 唤醒”。在家中 Wi-Fi 下需要局域网配对及有效的唤醒参数；在外需要 Cloud 关联在线网关，并配置目标电脑的唤醒信息。网关未配置、离线等原因会显示在按钮说明中。
- **正在执行电源操作**：先等待状态同步完成，不要重复发送同一动作。
- **状态未知**：先检查网络并刷新；如果已保存局域网唤醒参数且手机仍在 Wi-Fi 下，可尝试局域网唤醒。
- **手机授权需要更新**：在 Cloud 网页重新生成二维码后扫码。已关联电脑的局域网直连仍可尝试使用。设置页区分“已保存授权”和 Cloud 实际连接状态。

电源指令会在手机上再次确认。页面每五秒检查一次状态；“唤醒包已发出”“指令已送达”都不代表电脑已开机，应等待电脑上线。电脑需事先启用网络唤醒，保持供电和网线连接。

## 只使用局域网，或继续使用旧版配对

首页的“只在家中使用？”和“连接”中的“独立局域网 / 旧版连接”都可进入独立模式。扫描电脑配对码即可直接控制，无需 Cloud；需要唤醒时，在本页填写并保存 MAC 与广播地址。未配置真实唤醒参数时，不会向代码中的示例 MAC 发送唤醒包。

此入口继续读取 `lanpower_pairing_v1` 和 `lanpower_remote_v1`，兼容 v1 Cloud/网关远程配对。Cloud v2 手机授权码应在主入口扫描。v1 与 v2 的局域网设置分别保存，互不覆盖。

## 在 iPhone 上预览

1. 仓库中的 `project.config.json` 使用公开占位值 `touristappid`。在本机微信开发者工具里设置自己的小程序或测试号 AppID；提交前保留公开占位值，不提交个人配置。`project.private.config.json` 已被 Git 忽略，项目没有使用或保存 AppSecret。
2. 在微信开发者工具中导入此目录，编译后点“预览”，用 iPhone 微信扫描开发者工具给出的二维码。
3. 远程控制需要在微信公众平台配置 Cloud 的 HTTPS `request` 合法域名；开发者工具的本地调试选项不能替代真机域名配置。
4. 局域网直连时，让 iPhone 连接与电脑同一局域网的 Wi-Fi，电脑可通过网线连接路由器；首次弹出微信本地网络访问提示时选择允许。

## 页面注册与开发检查

`app.json` 注册的两个页面均包含 `.js`、`.json`、`.wxml`、`.wxss`。请完整导入 `mini_program` 目录；遇到“页面 JSON 文件缺失”时确认 `pages/cloud/cloud.json` 和 `pages/index/index.json` 存在，再重新编译。忽略与公开文件检查规则只对这一份页面 `cloud.json` 放行，运行时私有 Cloud 配置仍禁止提交。

从仓库根目录运行：

```powershell
node tests/test_mini_program.js
node tests/test_mini_program_v2.js
```

两个测试覆盖页面配置完整性、授权码兑换、凭据轮换与失效提示、设备选择、LAN First、Cloud Fallback、网络切换、手动/下拉刷新、唤醒草稿与保存、WOL 和旧版远程入口。验证记录和真机验收边界见 [小程序 v2](../docs/mini-program-v2.md)。

小程序版本为 `2.0.0`、协议版本为 `2`；项目不包含真实 Cloud 域名、LAN Token、Gateway 凭据或远程配对二维码。
